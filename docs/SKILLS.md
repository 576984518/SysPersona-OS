# 技能总结（SKILLS）

> 一句话：**技能是把"做过一次"变成"下次不用想"。**
> 状态：v5.1.0 起成文；实体在 `%USERPROFILE%\.dsh\skills\<名字>\SKILL.md`，本页只做索引与判据。

## 一、现在有什么

| 技能 | 什么时候触发 | 它替你记住的东西 |
|---|---|---|
| `interaction-profile` | 任何对话开场、`1`、`继续` | 触发词表（`1`=有新内容，不是"没内容"）、决策风格、禁忌 |
| `session-recall` | "接着做 / 上次说到哪" | 唤醒顺序：接续包 → 一级索引 → 只取命中片段 |
| `capture-pipeline` | "我按了 F5 怎么没反应" | 抓取链路三条命令 + 变少不写 + 空壳页不算新内容 |
| `ctxguard-ops` | "上下文快满了 / 出个接续包" | 水位口径、800K 交接线、复制到剪贴板 |
| `ctxpack-tools` | "检索不准 / 重建索引" | 增量索引、混合检索、块缓存与编码坑 |
| `release-ops` | "发个版 / 打个 tag" | 该不该发、四段式 Release、发完必做四件事 |
| `diagnose-windows-sandbox-acl` | 沙箱里路径读写莫名失败 | 一次运行内自检并修 ACL，而不是猜 |

## 二、写技能的四条规矩

1. **只写"下次会用到"的**：命令、判据、坑——不写背景故事；
2. **判据要可验证**：能回答"怎么知道它成了"；
3. **坑必须写进去**：踩过一次的坑不进技能，就会踩第二次；
4. **实体与索引分离**：技能正文在 `.dsh\skills\`，本页只列"有什么 + 何时用"，避免两处描述打架。

## 三、什么样的经验才配变成技能

| 值得 | 不值得 |
|---|---|
| 做成功过一次、且以后还会重复的动作 | 一次性的迁移、临时排障 |
| 有明确触发词（用户一句话就能叫出来） | 需要读长文才能判断的场景 |
| 判据可以写成"是/否" | "感觉更好了" |

反例留档：曾经把「控制台闪烁要不要上 Cordis 插件」写成待办，结论是**不做**——
这种"决定不做"的结论应该进 `DECISIONS`，不该变成技能。

## 四、验收

| 判据 | 怎么验 |
|---|---|
| 叫得出来 | 说触发词，AI 直接按技能执行，不需要再解释背景 |
| 跑得通 | 技能里的命令原样可执行（路径不写死，走变量） |
| 不过期 | 改了脚本名，技能里的路径同步改（改一处要扫全库） |
| 不重复 | 同一件事只有一个技能负责，交叉引用用链接 |
