## 一句话设问

**把这五版——唤醒 / 记忆网络 / 空闲自主 / 客户端与容灾 / 界面接管——拼在一起，它到底是一台什么东西？换一台设备还成立吗？**

## 设计思想

前五版是**逐块长出来的**：v5.3 让它在醒来后知道该干什么，v5.8 让几台机器接成一个记忆体，
v5.9 让它在没人发话时自己找事，v6.1 让它能和不同的外壳相处、出事知道往哪退，
v6.3 让它能操作客户的界面并自证。每一版都各自成立，但**没有人从"一台设备"的角度把它们串起来过**。

这一版只做一件事：**把它们抽象成一台"接了记忆的机体"该有的运行学**，并给出移植判据。

守两条：

1. **机体可以换，记忆必须连续。** 换模型、换客户端、换硬件都不改身份；不遵守运行设计的机体等于没接住。
2. **每个动作都要能自证。** 没有回读判据的动作，等于"我以为我做完了"——这一条是四版共同的底座。

## 步骤（一台设备跑一圈）

```
0 醒        设定重载（短指针，不灌全文）
1 读现场    台账 / 状态文件 / 代码 —— 不许不读就猜
2 判断      能力 × 设定 × 权限，三者取交集（这一档够不够、这事能不能做）
3 前台回话  结论 + 下一步；5 秒以上的活丢后台
4 干        挑"最可核对"的路：接口 > 状态文件 > 键盘注入 > 屏幕识别
5 证        回读状态；对不上重来，最多 3 轮；仍不成 → 告警 + 等人
6 记账回落  降权 / 降档 / 停本地服务，回到最小消耗状态
```

## 要实现什么

| 目标 | 机制 | 算完成的标准 |
|---|---|---|
| 换设备不改行为 | 能力清单六项（屏幕可读 / 输入可注 / 结构化接口 / 进程可管 / 持久存储 / 出口通道） | 缺哪项都写成降级路径，不假装有 |
| 动作可核对 | 判据四档：结构化状态 > 日志台账 > 界面文字 > 截图（只截一张） | 每个动作都有回读判据 |
| 出事能退 | 四层降级：进程 → 配置 → 模型 → 通道 | 每次降级留痕，且不动权限 |
| 没人发话也安全 | 意图先写下来、优先级、可抢占、配额按档位 | 红线在任何档位都不放宽 |
| 活派得出去也收得回 | 两道门 + 重试上限 3 + 失败告警 | 不会永久卡在"处理中" |
| 新设备可验收 | 八条最小清单（第 8 条"能接网"单机写"不适用"） | 八条全过才算"接住" |
| 多台设备一个记忆体 | 节点服务：`/manifest` 清单 + `/blob` 取块，只增不删、先校验后替换 | 不在网络上合并冲突，删除不同步 |

## 细节（按职责，不按文件）

**为什么把"自证"提到最高优先级。**
四版里最贵的教训都在这：注入成功 ≠ 生效（`/compact` 发出去水位不降）、
回车成功 ≠ 选中（模型列表要"粘贴后立刻回车"）、点了 ≠ 改了（档位缓存要回读 `pending`）。
所以运行设计把"回读"写进主循环第 5 步，**没有它，前面四步都不算数**。

**为什么判据要分四档、越靠前越用。**
在 2 GB 显存的机器上，用"每 0.25 秒截一次图做像素比对"确认界面，直接把整机卡死。
改成"读状态文件 + 事后核对一次"后，既准又几乎不花钱。截图退成"只截一张、留证用"。

**为什么降级不让人点头、提权才要人点头。**
降级是"退"，提权是"进"。退错了顶多慢一点，进错了就把护栏拆了。
所以：切模型、换客户端、拉起进程都不问；改权限、关机注销、代勾风险确认一律问。

**为什么本地这一级要写"只够给谁用"。**
本机 2 GB 显存装不下 64K 上下文的 KV 缓存，本地小模型当不了客户端主模型。
设计里就写明"这一级只够给后台调用"，而不是含糊成"已支持降级到本地"。

## 证据（四版各自的实测，本次只做串联不改行为）

- **v5.3**：`tools/persona/selftest.py` → **PASS 36 / FAIL 0**（临时库，不碰真数据）；
- **v5.9**：`--task 日常` 时本机模型停着，自动改用**硅基免费档**，**首字 0.27 秒、费用 0**；
  配额按档位生效（免费/本地 12 次每小时，收费 3 次每小时），默认最小；
  **这句只说明「后台自己的调用」能省到 0 元**——硅基免费档的上下文只有 32K，当不了客户端主模型（见下条与边界）；
- **v6.1**：客户端契约（img/wm/actions/open）与容灾四层成文；托盘按配置动态生成二级菜单。
  **但要分清两种用法**：后台调用可以在 DeepSeek ↔ 硅基免费 ↔ 本地之间自由降级；
  **客户端（Hermes）只认 ≥64K 上下文**，免费档 32K、本地 4K 都进不去它的主模型位——所以对 Hermes 而言，真实可用档只有 DeepSeek 一档。
- **v6.3**：换模型 `flash → v4-pro → flash` 两轮 PASS（`pending.model` 自证）；
  推理档位 high/low 各一次成功并**默认禁止切到 off**（掉下去自动拉回）；
  权限 `preset=auto` 可读、**知情确认不代勾**；关机/注销需人下单（一次性单 + 120 秒有效）。
- **v5.8**：节点服务 `persona_lanbus.py` 入库——`/health` 免令牌不含路径、`/manifest` 与 `/blob` 走
  `Bearer` 令牌（取不到令牌服务端拒绝启动）、默认只听 `127.0.0.1`、白名单 `index/ archive/ 续接/`、
  写盘走 **临时文件 → fsync → replace**、sha256 不符就不替换；客户端**只增不删**，服务端不合并冲突。
  本次只把它**并入运行设计**（§四·六），不改代码。
- **本次新增**：`docs/DEVICE_RUNTIME_SPEC.md`（运行设计全文），把上述五版的判据、降级链、
  自主与派发、设备能力清单、移植八条验收、记忆网络、以及"明确不成立的地方"写成一份可移植的规格。

## 边界

- 这**不是**通用机器人操作系统：不涉及电机控制、实时调度、功能安全认证；
- **不保证跨平台**：实现仍是 Windows（计划任务、注册表自启、进程枚举、界面注入）；
- **不保证界面稳定**：客户端改版会让坐标失效，所以坐标必须可重量；
- **降级链要按用途分开读**：后台调用够用（云端付费 → 硅基免费 → 本地）；客户端主模型不够用（只有 ≥64K 的 DeepSeek 一档）。本机 2 GB 显存装不下 64K 的 KV 缓存，本地这一级已定不往客户端主模型上凑（BACKLOG B108）；
- **不保证模型行为**：换模型就换行为，唯一能守的约束是"接住的模型必须遵守设定"；
- **记忆网络不是加密方案**：传输是明文 HTTP，保密性靠虚拟网段；不做冲突合并、不做删除同步、
  没有跨节点锁——多台同时改同一路径时，后落盘者赢。

## 追加（同日 21:2x）：记忆层单独成一章——合并＝同步，保存按来源

人：「把 1.4 版改为记忆合并，注意只是记忆同步，保存还是按来源保存，然后加入这一版」。

- 规格新增 **§四·五 记忆层**：合并只做“收进来”，不做“合成一条”；不做跨来源去重、不做摘要替换；
  来源是一等字段（设备 / 分支 / 会话 / 模型）；对账不覆盖——同步前后来源库字节不变；
- 推论：既然记忆按来源分开保存、检索是客观的，“**分身合并**”就不是一个操作，而是**读自己的记忆**，
  因此它不该出现在“必须人点头”的清单里（同日已从设定里删掉）；
- 对应的历史版本页（v1.4.0）已就地改成这个口径：合并＝同步，不并库、不覆盖、不摘要。

## 追加（同日）：记忆网络也并入——v5.8 这条线不能漏

人：「把记忆网络也加入 6.4」。

前四版串起来只解决了"一个机体怎么运转"，**没回答"几台机体怎么共用一个记忆"**。
v5.8 那条线（节点服务）正是这一块，所以并进来，规格加 **§四·六 记忆网络**、部件表从七个变八个、
移植验收从七条变八条（第 8 条"能接网"单机可写"不适用"）。

要点只有一句：**搬运不是合并**。节点服务只负责"把索引和档案从 A 搬到 B"，
它不合并冲突、不同步删除、也不当加密通道——所以它和"保存按来源"是同一套口径的两半：
**网络只管搬，来源各自留**。
