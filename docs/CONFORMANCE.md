# 一致性声明（Conformance）

本文件定义**第三方实现如何证明自己符合**《[安全与加密规范](SECURITY_SPEC.md)》。
规范是契约，实现可以任意语言、任意加密库；这里只规定「怎么算符合」。

> 原则：**可验证的声明才算声明。** 没有测试证据的「兼容」不成立。

> **2026-11-08 修订**：本页等级原写作 L1/L2/L3，与 `LAUNCHER_SPEC.md` §17 的运行时档位 L1–L4
> 同名不同义。现改为 **C1/C2/C3（Conformance 等级）**；**L1–L4 一律专指运行时实现档位**。


---

## 1. 分级

按能力分三级，实现可以选择只声明 C1/C2。

| 级别 | 包含 | 必须通过 |
|---|---|---|
| **C1 容器核心** | 容器格式、KDF、AEAD、头部 MAC、内核签名、失败语义、明文迁移 | KAT + N1–N10、N13、N14 + 一次互操作 |
| **C2 恢复与轮换** | C1 + 助记词恢复 + 改口令 + 离线备份流程 | C1 + N12 + 备份恢复哈希一致 |
| **C3 身份与模板** | C2 + Ed25519 模板签名 + fork 语义 + `device-key` 绑定 | C2 + 模板篡改失败（N11）+ fork 新 UUID |

未声明的级别不要求实现；但**不得**把未实现的级别写进声明。

## 2. 必过测试

### 2.1 已知答案（KAT）

[`SECURITY_SPEC.md` 附录 B](SECURITY_SPEC.md#附录-b--kat-向量) 的全部向量必须逐字节一致：

- HKDF-SHA256（RFC 5869 Case 1）
- HMAC-SHA256
- AES-256-GCM（空消息 / 16 字节零块）
- BIP39 零熵 → 24 词
- 规范化 JSON 字节

### 2.2 负向矩阵

[`SECURITY_SPEC.md` §20.2](SECURITY_SPEC.md#202-负向测试矩阵必须) 的 N1–N14：

- 至少 C1 通过 N1–N10、N13、N14；
- C2 追加 N12；
- C3 追加 N11。

失败必须是**规范错误码**，并且发生在写盘之前。

### 2.3 互操作

至少与另一个独立实现交换一次：

1. 本实现写一个容器，另一实现解开（文件哈希一致）；
2. 反向再来一次。

两边都是自己写的代码不算互操作（那只是自己和自己一致）。

### 2.4 失败语义

- 错口令 / 错设备 / 缺 wrap 必须同一句用户可见文案；
- 未知算法必须 `E_UNSUPPORTED`，不得静默降级；
- 验签失败必须拒绝启动。

## 3. 声明文件

在仓库放一个 `conformance.json`，并在 PR/Issue 里附证据链接：

```json
{
  "impl": "syspersona-rs",
  "version": "1.0.0",
  "language": "rust",
  "levels": ["C1", "C2"],
  "algorithms": {
    "kdf": ["argon2id", "scrypt"],
    "aead": ["aes-256-gcm"],
    "mac": ["hmac-sha256"]
  },
  "evidence": {
    "kat": "https://example.org/kat-report.html",
    "negative": "https://example.org/negative-report.html",
    "interop": "https://example.org/interop-with-reference.md"
  },
  "deviations": []
}
```

- `deviations` 必须逐条写明「偏离了哪一条 MUST、为什么、影响是什么」。空数组表示无偏离。
- 声明只覆盖 `algorithms` 里列出的算法；换成未列出的算法等于新声明。

---

## 4. 不算通过的几种情况

- 只跑正向用例，不跑负向矩阵；
- 解密失败时给出「口令错误 / 数据损坏」的不同文案（泄露预言机）；
- 遇到不认识的 `alg` 时回退到某一种默认算法；
- 用 HMAC 充当公开模板签名（第三方无法验证）；
- 声明 C3 但没有实现 fork 的新 UUID / 空记忆语义；
- 互操作只是「自己两个版本之间」测过。

---

## 5. 版本与兼容

- 规范 `1.x` 内保持向后兼容：新增算法只扩展注册表，不改字节布局；
- 破坏性变更进 `2.0`，并要求实现同时声明 `1.x` 的读取能力至少一个大版本；
- 容器 `version` 字段与规范主版本同步；读取方遇到更高版本必须拒绝。

---

## 6. 提交方式

- PR：把 `conformance.json` 放在 `docs/conformance/<impl>.json`，附证据链接；
- Issue：标题 `[conformance] <impl> C1/C2/C3`，正文贴声明与证据；
- 维护者只核对「证据是否存在、是否覆盖声明的级别」，不评价实现语言或性能。

> 一句话：**声明级别、给证据、写偏离。** 三者齐了，才算符合。
