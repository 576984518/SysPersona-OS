# v6.5.0 · 新设备最小化部署接入

> **这一版只回答一个问题：一台新设备，最少要装多少东西，才能成为本网络的可用节点？**

---

## 一、设计思想

人先问出了那个悖论：「想部署必须先复制，复制了才能连节点」；紧接着又给了现实约束：
「不要复制所有的会话」「3 天的会话备份快 2 个 G」。

所以这一版不做"搬家"，只做**点火**：

- **复制只负责点火，不负责搬家。** 引导包只装脚本、配置、几份说明；会话/归档/索引/备份一个都不装。
- **三层互不依赖。** 引导失败才停；连不上照样是可用节点（降级不罢工）。
- **包必须能自证。** 每文件 sha256 写进 MANIFEST，`verify` 不过就不许装；包里不许有密钥。
- **契约先于实现。** 端口、监听面、凭据、同步方向写进规格，之后谁实现都照这张表。

## 二、步骤（一条链路）

```
新设备
  │
  ├─① 复制引导包（离线可完成）          1.7 MB（不带运行时）/ ~0.4 GB（带）
  │     └ verify：按 MANIFEST 校 sha256 ── 不过 → 停，不装
  ├─② 认身份：默认配置 → 探测 → 机器档 → 生效
  │     └ 认不出 → 生成新机器档（绝不猜成旧机器）
  ├─③ 连节点：填统一令牌 → /health 探活 → sync --dry-run 看清单
  │     └ 连不上 → 停在【单机可用】，不报错、不空转
  └─④ 自检 → 记账
        └ 全绿 → 【节点可用】
```

## 三、要实现什么（目标 → 机制）

| 目标 | 机制 | 算完成 |
|---|---|---|
| 新设备不用搬数据也能跑 | `persona_bootstrap.py` 只收 `scripts/` `config/` `docs/` | `list` 里没有 sessions/archive/index/备份/ops/续接 |
| 包不会被偷偷塞进数据 | 禁收目录命中即**拒绝打包**（退出码 3），不是跳过 | 手动往脚本目录塞一个 `sessions/` 子目录 → `pack` 返回 3 |
| 包不会被当成泄露源 | 文件名/内容双扫（`token` `secret` `.env` `sk-` 长串、私钥头） | 造一个含假 key 的文件 → `pack` 返回 3 |
| 装错能立刻发现 | `MANIFEST.json` + `verify` | 改坏包里一个字节 → `verify` 报哈希不符 |
| 部署口径不靠口头传 | `docs/DEPLOY_MIN_SPEC.md` 定端口/监听/凭据/同步方向 | 规格里五条约定齐全 |

## 四、细节（按职责）

**打包器**（`tools/ctxpack/persona_bootstrap.py`）：为什么单写一个而不是塞进现有 `persona_pack.py`——
后者是"上下文提取与归档"，职责不同；点火包要的是**排除法**（只收白名单目录）与**红线检查**，
两件事混在一起早晚会有人给归档脚本加个开关就绕过了红线。包内路径一律正斜杠（zip 里写反斜杠，
别的解压工具会把反斜杠当文件名的一部分——这是实测踩到的）。

**清单**（`MANIFEST.json`）：每文件 `rel/size/sha256` + 总量 + 生成时间 + 版本。
带运行时的包（约 0.4 GB）也走同一套清单，不因为大就免检。

**脱敏**：顺手把源码注释里剩下的本机盘符路径改成通用说法（"另一块盘的 `ProgramData`"），
公开仓库的硬路径扫描保持零命中。

## 五、证据

```
$ python persona_bootstrap.py list
会打 111 个文件 / 1.7 MB
  config\README.md / config\_默认.json / config\机器\…
  docs\先读我.md / 使用说明.md / 接入手册-新客户端.md / 自检清单.md
  scripts\…（104 个）

$ python persona_bootstrap.py pack --out <目录> --version 6.5.0
文件 111 个 / 1.7 MB（含 MANIFEST.json）
包里没有 sessions / archive / index / 备份 / ops / 续接；也没有任何密钥

$ python persona_bootstrap.py verify <zip>
校验 SysPersona-bootstrap-6.5.0-20261112.zip：OK 111 · 哈希不符 0 · 缺 0

包内顶层：{'scripts': 104, 'config': 3, 'docs': 4, 'MANIFEST.json': 1}
含 .bak- 的条目： []
```

对比：整库 5.0 GB / 8453 个文件 → **引导包 1.7 MB / 111 个文件**（不带运行时）。

## 六、边界

- 端口的**多地址监听**、**防火墙一键放行**、**`health` 子命令**尚未实现，本版只把契约写进规格；
- 没有"从远端拉引导包"的能力：引导包必须能离线用，这是故意的；
- 没有双向自动合并：两节点同时改同一份记忆的冲突留给下一版，冲突时停下报人；
- 机器配置的"默认 → 探测 → 机器档 → 生效"四层属于 **v6.6.0**，本版不展开；
- 清理（先搬后删的清道夫）属于 **v6.7.0**，本版不带。
