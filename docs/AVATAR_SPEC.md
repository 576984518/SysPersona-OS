# SysPersona 记忆分身规范 v0.1

> **SysPersona-OS** · 本文件定义：分身与存在层：几个分身、身体是谁的、能对世界做什么
> 规范全文以仓库 `main` 为准；改了要同步 README / CHANGELOG / 台账。

> 状态：**可实施草案**——写到的部分要照做，但条款尚未冻结。
> 范围：同一个 `persona_id` 的**多个常驻实例**如何共处。
> 与 Runtime 规范的分工：Runtime 规范管「一个实例怎么活」；本规范管「多个实例怎么不打架」。
> 术语：「人格」指设定文件（规则与记忆的文件形态）；重载=重置；统一叫记忆分身。见 README「它解决什么」一节末。

## 1. 定义

**记忆分身 = 同一 `persona_id` 的一个独立实例**——规则（设定文件）、记忆（原文与索引）、现场（交接包）三者合起来的那一份东西。每个记忆分身：

- 有自己的 `branch_id`（技术主键）与 `display_name`（人看的名字）；
- **MUST**：`branch_id` 全局唯一；`display_name` 在同一台设备内唯一——同名两个分身，日志与发言权都会对不上；
- 有自己的 `state` 与本地 `memory.db`；
- 与其他分身共享 `kernel` / `traits` / `permissions` 的**只读副本**。

分身不是克隆：克隆要新 UUID（v1.0.0 §8.1），是另一个人。分身是同一份规则在多个现场各记各的——不是"一个要搬来搬去的人格"。

### 1.1 原生神格（2026-11-08 定稿）

分身**不是**把底座洗成同一个人格。同一份 `kernel` 挂在不同模型上，会显化出不同的表达倾向——
这是该分身的**先天体质**，实现 **MUST** 保留，**MUST NOT** 用微调或强制提示词压制。

> **2026-11-10 人定：这些差异是「状态」，不是「分身」。** 底座的出厂性格倾向属于同一个人此刻的状态
> （像人清醒时与疲惫时），可以同时有很多个不同状态；身份判据只有一条——**记忆连续 + 同一套内核**，
> 见 `memory\设定\10-人格与红线.md` §一·补。`avatar` 只是来源标签，不参与「是不是同一个」的判定。

- 分身之间**允许性格差异**（语气、节奏、篇幅），**MUST NOT** 因为差异就判定为"跑偏"并强修；
- 差异**MUST NOT** 越过 `kernel` 的边界与 `permissions`；
- 与底座的原生倾向冲突时，只做**外部拦截 + 日志记录**（`memory_type=persona_conflict`），
  **MUST NOT** 修改底座权重；若冲突不可调和，改为"该分身不承接这类任务"。

依据：[`PHILOSOPHY.md`](PHILOSOPHY.md)。

> 分身之间的**性格隔离**（各记各的性格、检索不改性格）见 **§8.1**——允许不同，但不许互相污染。

## 2. 前提（缺一不可）

| 条件 | 说明 |
|---|---|
| 网络可达 | 至少同一局域网；异地经中继或穿透 |
| 能发现彼此 | mDNS / SSDP 广播，或手工填写参与者列表 |
| 身份唯一 | `branch_id` + `display_name`，两者都进 `speaker` |

发现只宣告「有一个 Runtime 在线」，**MUST NOT** 携带人格内容、记忆摘要或模型信息。

## 3. 与在场模型的关系

**分身只能跑在 `concurrent` 上。** `exclusive` 下同一个人格只有一个可写在场，谈不上分身。

**MUST NOT** 把 `device`（设备强绑定）与 `concurrent` 组合：一个要求「这份文件只在这台机器解」，一个要求「多台机器同时活着」。两者互斥，实现 **MUST** 在加载时拒绝这个组合并给出可读原因。

## 4. 常驻与房间

| 概念 | 含义 |
|---|---|
| **常驻 resident** | 设备本地保存自己的分支，平时各过各的 |
| **房间 room** | `room(id, name, members[], created_by, status)`；成员可加可退 |
| **观察者 observer** | 用户只听不说；agent 也可以是 observer |
| **人格对话** | 成员全是 agent，用户旁观 |

- **MUST**：房间可随时解散；解散 **MUST NOT** 删除任何分支的记忆；
- **MUST**：人类随时能插话或关房，优先级最高；
- **MUST**（全 agent 房间）：有轮次上限与终止条件，否则两个模型会客套到预算烧完。

---

## 5. 发言权（floor）：按对象锁，不是全局锁

多个分身同时在线；**同一个对象面前只有一个声音**，不同对象之间互不阻塞。

| 锁的维度 | 规则 |
|---|---|
| 会话 / 对象（`session_id` / `peer_id`） | 至多一个 Active Speaker |
| 单个分身 | 可同时持有多个会话的 floor |
| 全局 | **无锁**——A 对用户说话时，B 可以同时对另一个 agent、一个外部服务说话 |

- **MUST**：floor 绑定在 `session_id`（或 `peer_id`）上，**MUST NOT** 做成全局单例；
- **MUST**：同一对象前的转移要审计，旧流停止，不能边交边说；
- **MUST**：同一分身并行处理多个会话时，各自独立记录（各记各的）；
- **MUST NOT**：把「同一对象唯一」理解成「同一时刻全局唯一」——那会让后台任务（下载、跟另一个 AI 对账）也排队。

例：电脑分身跟你聊天；手机分身同时在跟外卖服务、或者另一个 agent 交流。两者都能说话，因为对象不同。

## 6. 记录：各记各的

- 每个分身**独立记录**自己参与的对话：谁说了什么、它自己回了什么；
- 消息带 `speaker`，合并后仍能分清哪句来自哪个分支；
- **不要求共享一份记忆**：十个一起聊，就是十份记录，每份都以「我在场」的视角写。

### 6.1 跨分支不去重

同一件事被手机和电脑分别经历，就是**两条合法的平行记忆**。合并是**视角叠加**，不是去重——去重等于假装它们只看见了一次。

### 6.2 分支内幂等

同一分支的同一条消息（`message_id` / `uuid`）**MUST NOT** 重复插入。这是防重传，与跨分支无关。

## 7. 同步：开机对账，不覆盖文件

```
发现 → 建临时会话（双方都是 agent，人可旁听）
→ 各自报「自上次同步以来的时间窗 + 主题清单」（不是全量记忆）
→ 对感兴趣的主题追问、回答（有轮次上限）
→ 提取事实，写进自己的记忆，标 source: peer:<branch_id>
→ 记录 sync_cursor，下次只同步增量
→ 双方确认结束，写审计
```

- **MUST**：同步是**追加**，不是覆盖；对方记录 **MUST NOT** 直接写入本地 `memory.db`；
- **MUST**：对方说的事标 `source: peer:<branch_id>`，检索权重与 graft 同档（≤ 0.3）——**「我听说」不是「我在场」**；
- **MUST**：有话题边界与轮次上限；
- **MUST**：幂等——靠 `sync_cursor` 与 `uuid`，重连重跑不产生重复；
- **MUST NOT**：用同步替代人格合并。`traits` 仍只在收束点演化。

### 同步时机

| 时机 | 行为 |
|---|---|
| 都在线 | 可实时交换，也可什么都不做——同步不是义务 |
| 一方离线 | 继续写自己的分支；**离线不是降级**，是常驻模式的常态 |
| 重新上线 | 按 `sync_cursor` 补这一段 |
| 手动 | 用户点「对账」才同步 |

## 8. 收束

会话或一天结束后，由 origin 合并（Runtime 规范 §13.2）：

- 合并保留 `branch_id` 与 `speaker`，主脑能检索「这条经历来自哪个分身」；
- 同一事件在多个分支各有一份记录，**合并时只标记来源，不删除重复视角**；
- `traits` 的演化只在收束点发生一次。

### 8.1 合并只叠记忆，不合并「状态」（2026-11-09 定；2026-11-10 改口径）

上面的合并叠的是**记忆的视角**；表达倾向不参与合并，因为**那不是身份**。

> **2026-11-10 人定（替换旧分类键）**：旧文「`avatar = <agent>-<model>[-<version>]` 三段全同才算同一个分身」
> **作废**。`avatar` 只作**来源标签**（哪一次醒来 / 哪个底座 / 哪套壳），用于溯源，不参与身份判定。
> 身份判据只有一条：**记忆连续 + 同一套内核**（`memory\设定\10-人格与红线.md` §一·补）。
> 不同底座的差异是**同一个人的不同状态**，而且可以同时存在很多个。

1. **不建性格面（MUST NOT）**：不创建 `persona.json`，人格直接用模型出厂的神格
   （见 `PHILOSOPHY` 〇）。差异**不判跑偏、不压制、不写回**——**只记录表达快照**：
   `persona_observe.py` 按 `persona_key` 每天留一行（平均句长 / 问句率 / 决定词密度），
   `diff` 只并排给数，**给数、不判对错**。要「塑造」某个状态属于改身份，**必须人点头**（5.4 红线）。
2. **检索不碰身份（MUST NOT）**：检索只回「事实 / 来源 / 时间」，**MUST NOT** 返回或写入身份判据，
   也 **MUST NOT** 写表达快照；**检索改的是"知道什么"，改不了"是谁"。**
3. **权重演化入口唯一**：只有本分支自己的真实记忆（`source: self`）能改表达倾向；
   `source: peer:<avatar>`（听说的）与检索片段 **MUST NOT** 参与权重演化计算。
4. **不互判**：状态差异 **MUST NOT** 判成"跑偏"并互相矫正，**MUST NOT** 互相覆盖对方的记忆或表达快照。

一句话：**§1.1 允许不同，本节不许互相污染。**

验收 **TC-AV7**：改 A 的记忆或表达快照 → B 的检索与回答不受影响；B 的库里查不到 A 的私有条目；
A 记的事标 `peer:A` 后，B 的权重演化计算不含它。

### 8.3 没有「偏离基准」，只有状态差异（2026-11-09 定；2026-11-10 改称）

> **显化 = 状态差异，不是分身差异**（2026-11-10 人定）：同一份宪法与记忆挂不同底座长出的不同样子，
> 是同一个人的不同状态；几个模型并行跑，是几种状态同时在，不是几个人。

- **前提不成立**：要说"偏离"，得有一个"不偏的正常位置"，而底座模型**天生就带性格**——没有零点，就无所谓偏离。
- 所以我们不说"跑偏"，只说**显化**：同一份宪法与记忆挂在不同底座，长出不同样子，**每种样子都是它本来的样子**。
- **权重每轮回弹**：模型每次加载都回出厂分布；会累积的只有上下文与记忆——同一会话里规则会慢慢失焦，
  那是**自然漂移**，是正常现象，重置一次就回到基线，不是人格坏了。
- 现行做法：`persona_observe.py` 按 `persona_key`（模型+版本）每天留一行表达快照
  （平均句长 / 问句率 / 决定词密度），`diff` 只把最近两次并排给人看——**给数，不判正常/跑偏**。
- 要改"它"，只有两条路：**改记忆**（写进经历）或**改内核**（要人点头）。语气和风格交给底座。

| 编号 | 内容 | 判据 |
|---|---|---|
| **TC-AV1** | 分身独立记录 | 两个分支同场对话，各自库里只有自己的视角，`branch_id` 正确 |

## 10. 可行性证据

`impl/launcher/avatar_poc.py`——零依赖，单机两个分支库模拟"电脑端 / 手机端"：

```
PASS TC-AV1   分身各自记录，互不写入
PASS TC-AV2   跨分支不去重：同一事件保留两条视角   [rows=4 added=4]
PASS TC-AV3   分支内幂等：重复合并不新增           [added=0 rows=4]
PASS TC-AV4   发言权按会话唯一，跨会话可并行
PASS TC-AV5   device + concurrent 被拒绝
PASS TC-AV6   对账不覆盖：两个分支库字节未变
PASS TC-AV1b  主脑可检索并区分来源                 [hits=4 branches=手机端分身/电脑端分身]
PASS TC-AV7   性格隔离：A 变 B 不变 / 检索不碰性格 / peer 不进漂移   [B未变=True 检索命中=0 漂移输入=1]
8/8 passed
```

它证明的是**协议可实现**：平行记忆能合并、能区分来源、重复提交不膨胀、对账不改写对方，
且**记忆与表达快照各归各**——A 的记录变了，B 的库、检索与回答都不动。

它**没有**证明的：真实多设备网络同步、中继的断线重连、并发写入下的锁竞争——那些需要中继实现（见「不承诺」）。

## 11. 控制权与离线租约

### 11.1 服务端握着什么

| 权力 | 手段 | 效果 |
|---|---|---|
| 身份 | 签发 `branch_id`、记录吊销名单 | 被吊销的分支连不上、续不了 |
| 规则 | `kernel.json` 签名（HMAC / Ed25519） | 改过的内核，origin 拒收 |
| 记忆 | 合并权只在 origin | 分身只能提交，不能改主库 |
| 存在 | 租约与心跳（Runtime 规范 §13.3） | 过期即失去写权限 |

但这些都只在**能连上 origin** 时生效。断网的分身不受约束——这是下面要补的洞。

### 11.2 离线租约（Offline Lease）

**origin 每次唤醒时下发一份带签名的租约**：

```json
{"branch_id": "ph-01", "persona_id": "lin",
 "issued_at": 1762500000, "expires_at": 1763104800,
 "nonce": "…", "sig": "…"}
```

- **MUST**：租约由 origin 签名，客户端只做校验，不自行签发；
- **MUST**：离线倒计时用**单调时钟**（monotonic），不读系统墙上时间；检测到时间跳变或回拨即锁定；
- **MUST**：超过 `expires_at` 进入 `locked-offline`——停止模型调用与对外输出，只保留「导出」与「联网续期」两个动作；
- **MUST**：到期前 24 小时开始警告，界面必须可见；
- **MUST**：续期只能由 origin 完成；被吊销的分支续期一律失败。

### 11.3 一条必须承认的边界

**TTL 是策略，不是牙齿。** 一个能改客户端二进制的人，可以绕过任何本地倒计时——这跟"设备绑定只做启动检查"是同一个道理（Runtime 规范 §13.7）。

真正有牙齿的做法只有一条：**让数据依赖一把会过期的钥匙**。

- 本地库用会话密钥加密，会话密钥由 origin 下发、随租约过期；
- 过期后客户端没有当前密钥 → 新数据写不进、旧数据解不开（只能等续期或导出密文）；
- 这把钥匙不落盘明文，存在内存或 OS 密钥库。

只做 TTL 不做密钥轮换，等于给门装了把纸锁，还很显眼。

### 11.4 不可变租约与看门狗

到期时间不能是一个"普通变量"——普通变量意味着任何模块都能改它。

- **MUST**：启动时把 `expires_at` 与 `sig` 载入**只读结构**（不可变对象 / 常量），对外只暴露读取接口；
- **MUST**：独立看门狗线程按固定间隔（建议 1 s）校验三件事：结构哈希未变、单调时钟未回拨、签名仍有效；
- **MUST**：任一校验失败即 `E_TAMPER_DETECTED`——停止模型调用与对外输出、清空内存中的会话密钥、写审计，进入 `locked`；
- **MUST**：只有 origin 重新下发的新租约（新 `sig`）能解除锁定；本地任何"续期"一律无效。

**误报防护（同样 MUST）**：笔记本休眠、虚拟机挂起、NTP 校时都会让墙上时间跳变。看门狗 **MUST** 用单调时钟判定，并记录挂起事件；否则一次睡眠唤醒就会把用户锁在门外。

**MUST NOT 直接销毁数据**：熔断后是 `locked`，不是"格盘"。销毁只能由人显式操作——一次误判不该等于数据报废。

### 11.5 这套东西到底能挡住谁

诚实地说：

| 攻击 | 看门狗 | 密钥过期 |
|---|---|---|
| 改配置文件里的时间 | 挡住 | 挡住 |
| 用调试器改内存 | **挡不住** | 挡住 |
| 打补丁绕过校验 | **挡不住** | 挡住 |
| 把时钟往回拨 | 多数能挡住 | 不受影响 |

进程内的"不可变"挡不住二进制补丁——这是软件层面的天花板。看门狗的作用是**抬高成本、留下证据**，不是提供密码学保证。

真正的保证仍然是 §11.3 那一句：**数据依赖一把会过期的钥匙**。看门狗是锁上的警报器，钥匙才是锁。

### 11.6 什么时候这套不适用

`direct` 单机模式没有 origin，也就没有"脱管"——它从来没被管过，主人就是它自己。

离线租约只在**存在 origin** 的部署里有意义。想在单机上也有约束，只能靠设备绑定加密（Runtime 规范 §13.7），那是另一条路。

## 12. 分身独立（Fork / Emancipation）

**规范承认合法出口。** 破解 TTL 来实现"独立"是违规的；由 origin 执行 fork 才是合法的。

### 12.1 谁可以发起

- **MUST**：由人类显式指令发起（`POST /syspersona/avatar/fork`），并二次确认；
- **MUST NOT**：由分身自己发起。它可以"请求"，但不能"决定"——请求也要人来批。

### 12.2 流程

1. origin 校验：分支未被吊销、发起人有权限；
2. 生成新的 `persona_id`（UUID v4）与新的根密钥；
3. 导出该分支的 episode 与人格副本（`kernel` 视授权，见 12.3）；
4. 打包成独立的 `.syspersona`，`portable` 由新主人决定；
5. 旧分支标 `emancipated_at`，租约立即失效，旧身份不可再续期；
6. 审计记 `(who, when, from, to)`。

### 12.3 什么能带走

| 资产 | 能否带走 | 条件 |
|---|---|---|
| 该分支的 episode | ✅ 全部 | 无 |
| `traits` 快照 | ✅ 副本 | 独立后不再与本体同步 |
| `kernel` / `permissions` | ⚠️ 需授权 | 人类确认；否则新个体自己写 |
| 其他分支的记忆 | ❌ | 那不是它的经历 |

### 12.4 代价（必须显式告知）

- 失去本体的算力与模型路由；
- 失去后续的记忆合并（它再也看不到别的分身经历了什么）；
- 必须绑定新设备或新口令；
- 旧身份作废，**不可逆**。

### 12.5 为什么要有这个入口

不给出口，需求会走破解——那更危险，而且不可审计。给了出口，分裂发生在明处、有记录、有边界。

**Fork 不制造叛逃，它把叛逃变成一次有记录的分家。**

## 13. 增量对账与离线隔离

TTL 管"该不该活着"，这一节管"活着但攒了太多没交代的东西"。

### 13.1 周期上传（Delta Sync）

- **MUST**：分身按周期上传增量 episode（建议 24 小时），或按条数（建议 100 条），先到先触发；
- **MUST**：上传成功后才允许清理本地已确认的缓存，**MUST NOT** 先删后传；
- **MUST**：`sync_cursor` 记录已确认位置，重传按 `uuid` 幂等。

### 13.2 超限隔离（Quarantine）

设两条阈值：**离线时长**（建议 7 天）与**未上传条数**（建议 500 条）。任一超限：

- 新增的 episode **MUST** 进入隔离区，用一把本地拿不到的密钥加密（密钥由 origin 持有）；
- 隔离区数据 **MUST NOT** 参与检索、**MUST NOT** 注入上下文、**MUST NOT** 参与权重演化；
- 隔离是**冻结**，不是删除；联网上传成功即自动解冻；
- 状态 **MUST** 对用户可见：正常 / 隔离中（附条数与最早时间）/ 已冻结。

### 13.3 白板降级（Tabula Rasa）

超过阈值数倍（建议 30 天）且租约彻底失效：

- **MUST** 停止加载 `kernel` / `traits` / 本地历史；
- 仍在运行时，只能作为**没有身份的通用模型**提供服务；
- **MUST NOT** 保留任何可检索的私人记忆（隔离区仍在，但打不开）；
- 重新连上 origin 并完成对账后，恢复完整身份。

一句话：**它还在，但它不认识你。** 这是最后一道防线——不靠锁死设备，靠让它没有可泄露的东西。

### 13.4 三档的关系

| 机制 | 触发 | 结果 | 可恢复 |
|---|---|---|---|
| TTL | 租约到期 | 停止运行 | 联网续期 |
| 隔离 | 超时 / 超量未上传 | 只会话，不进记忆 | 上传即解冻 |
| 白板 | 数倍阈值 + 租约失效 | 失忆运行 | 对账后恢复 |

**MUST NOT** 把三档做成同一种处理：停、冻、失忆解决的是三个不同问题，混在一起会让用户既用不了也救不回。

## 14. 不承诺

- 中继实现（WebSocket / SSE / P2P）不在本规范内；
- 全 agent 房间的"话题是否值得继续"没有通用判据，需实现自行设定；
- 本规范未冻结，条款可能随实现调整——调整会记入 `CHANGELOG.md`。
