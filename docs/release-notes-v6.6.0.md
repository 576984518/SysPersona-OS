# v6.6.0 · 不同设备的不同配置

> **这一版只回答一个问题：同一份记忆库，怎么让每台设备"各按各的来"，而换机时不用再手改脚本？**

---

## 一、设计思想

上一版（v6.5.0）解决的是"新设备靠一个 1.7 MB 的包就能跑起来"。但跑起来之后马上撞到第二个问题：
**每台机器长得不一样**——盘符不同、客户端装在不同卷、有的机器只有 4 GB 内存、有的机器上某个客户端根本没装。

过去的做法是把路径写进脚本，于是"换一台改一遍"成了常态。这一版把配置拆成四层，并立三条原则：

- **默认层只有"该找什么"，零机器路径**——它跟着库走，永远不需要改；
- **机器层是唯一的"这台机器就是这样"**——跟着库走，重装不丢；
- **生效层是产物，不是源**——随时可以由机器层重建，坏了一条命令回滚；
- **探测不许猜**：探不到写 `null`，绝不拿一个"看起来能跑"的路径冒充。

同时回答一个被忽略的问题：**"装了"不等于"要用"**。小主机上装着桌面客户端、本地模型齐全，
跑起来却会把机器拖死——所以配置里要能写"装了但本机不用"，而后台任务据此**整条跳过**，不报红。

## 二、步骤（四层 + 两组证据）

```
配置/_默认.json        ← 只写键名与"该找什么"（零机器信息）
        │ 探测（环境变量 → 每块盘常见位置 → PATH → null）
        ▼
配置/机器/<指纹>.json  ← 这台机器的实际路径 + 身份指纹 + 策略(clients)
        │ apply
        ▼
paths.json + 用户级环境变量  ← 程序真正读的那份（重装即失，跑一次即回）

身份判定：硬件组（CPUID/主板/全部 MAC/全部硬盘）  ∪  身份组（MachineGuid/机名/账户）
         任一命中 = 同一台；硬件变+系统没变 → 同一台并标「换硬件」；两组全不沾 = 新机器
```

## 三、要实现什么（目标 → 机制）

| 目标 | 机制 | 算完成 |
|---|---|---|
| 换机器不用改脚本 | 默认层零路径；机器层由探测生成 | `_默认.json` 里扫不到任何盘符路径 |
| 重装后能自己回来 | 机器档跟着库走；`new` 复用 `created`/`label` | 删掉 `paths.json` 后跑 `new`，配置回到位 |
| 探不到不瞎猜 | 三态显式：没装 / 装了不用 / 装了在用 | 未安装的客户端 → 消息是"未安装"，不是"掉线" |
| 小主机不被拖死 | `clients.<名字>.enabled=false + why`，后台任务整条跳过 | 任务消息为「跳过：本机不启用（why）」，不是 FAIL |
| 改坏能回滚 | 写 `paths.json` 前备份到 `配置/机器/<id>.paths.json.bak-<时间>` | 备份文件存在且可读 |

## 四、细节（按职责）

**探测**：`%ProgramData%` 在许多机器上并不与数据同卷（变量指向系统盘，客户端装在另一块盘的 `ProgramData` 下），
所以探测改成把每块**存在**盘的 `ProgramData` 都试一遍，**存在才算**。模型目录同理：库根与模型目录常常是**并排**关系，
所以先试 `<库根>/本地模型`、再试上一级。

**身份**：收一整组信号，判的时候按组。主板/BIOS 报占位值（`To be filled by O.E.M.` / 白牌通用 UUID）时**不采信**，
退到网卡 MAC + 硬盘序列号。id 一旦定下不再随指纹漂移。

**策略**：机器档里的 `clients` 是**人的决定**，探测不会自己编；`new` 重跑时保留上一份的 `clients`，
否则每次探测都会把人定的策略冲掉。

**生效**：`apply` 只做两件事——写 `paths.json`（含 `id` 与 `clients`）、设用户级环境变量（只增改，不删别人的）。

## 五、证据

```
$ python persona_machine.py detect
  hermes_home   <另一块盘>\Hermes Agent CN Desktop\data\hermes-home
  herdsman      <另一块盘>\Herdsman\herdsman.exe
  local_models  <并排目录>\本地模型

$ python persona_machine.py apply --id <id>
  备份旧 paths.json -> 配置/机器/<id>.paths.json.bak-<时间>
  写 paths.json -> <LOCALAPPDATA>\SysPersona\paths.json
  环境变量 …（12 个键：路径 + 模型 + 客户端家目录）

# 本机策略生效后的后台任务
localmodel    OK  跳过：本机不启用（本地模型十几 GB 权重，本机跑不动）
hermeskeeper  OK  跳过：本机不启用（4G 内存太小）
gate          OK  跳过：本机不启用（4G 内存太小）

# 自检
[自检] 15/15 OK
```

修复前后对比（同一台机器）：

| 项 | 修复前 | 修复后 |
|---|---|---|
| `hermes_home` / `herdsman` | 探成 `null` → 被判"本机没装" | 探到真实路径 |
| 本地模型目录 | 探不到（只试库根） | 探到（再试上一级） |
| 客户端策略 | 无此概念，装了就会去拉 | `enabled:false` → 整条跳过 |
| 客户端探针耗时 | 一轮 ~60 s（全表扫进程） | 一轮 ~20 s（进程/窗口各一条查询） |

## 六、边界

- 密钥**不进任何一层配置**：只写用户级环境变量，不写 JSON、不进库、不进包；
- 不做跨机器配置自动合并：两份机器档冲突就停下报人；
- 运行时的**自动安装**（在新机器上一键装 python/node/git）不在本版，仍走独立的还原脚本；
- 清理（先搬后删的清道夫）属 **v6.7.0**，本版不含其规格。
