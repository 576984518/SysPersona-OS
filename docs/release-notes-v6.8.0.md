# v6.8.0 · 节点连接的后半段：多地址、放行、探活

> **这一版只回答一个问题：说好了端口和凭据，凭什么能"一次就判断出是网络不通、还是令牌不对、还是对方没起"？**

---

## 一、设计思想

v6.5.0 把部署契约写进了规格：端口 8737、只监听虚拟网卡、一份共享令牌。但契约落地时缺三个动作，
每个都对应一次真实的困惑：

- **"本地也要能访问"** → 只绑虚拟网卡，本机反而连不上；绑 `0.0.0.0` 又把服务暴露到物理局域网。
  解法：**多地址监听**，回环与虚拟网卡各起一个，绝不为了省事监听所有网卡。
- **"端口开了没有"** → 防火墙是管理员的事，脚本不该假装自己能改。
  解法：`firewall` 默认**只打印那条原始命令**，`--apply` 才真执行；失败就把原命令交给人。
- **"连不上到底是哪一环"** → 带令牌重试是"一次试全部"，错了也不知道错在哪。
  解法：`health` **不需要令牌**，先回答"网络通不通"，再谈令牌。

## 二、步骤（诊断顺序）

```
① health（无鉴权） ── 200 ──→ 网络与端口都通，再谈令牌
      │
      ├─ 连接被拒（10061） → 服务没起 / 端口没开
      ├─ 超时（10060）     → 路由 / 防火墙 / 不在同一虚拟网段
      └─ 401               → 地址对了，是令牌问题
      
② sync（带令牌）→ 拿清单、按 sha256 增量拉
```

## 三、要实现什么（目标 → 机制）

| 目标 | 机制 | 算完成 |
|---|---|---|
| 本地与虚拟网卡都能访问，且不外露 | `--bind a,b` 逗号分隔，每个地址起一个 server | 两个地址都能 `health 200`，且 `0.0.0.0` 仍只在显式指定时才允许 |
| 放行只给虚拟网段 | `firewall --allow <CIDR>` 生成入站规则（仅该网段、仅该端口） | dry 打印命令；`--apply` 在无管理员时返回 3 并提示用原始命令 |
| 一眼分清故障层 | `health` 不发送令牌，按错误类型给结论 | 拒连/超时/401 三种结论都出现 |
| 探活不泄密 | `/health` 响应只有 `ok/node/version/root/files`，无路径细节、无令牌 | 抓包/看响应头看不到令牌 |

## 四、细节（按职责）

**多地址**：`ThreadingHTTPServer` 每个地址一个实例，各自线程 `serve_forever`；主线程只等它们退出。
任一地址监听失败 → 关掉已起的、返回 3，不留半开状态。

**firewall**：规则名固定 `SysPersona-LAN-<端口>`，重复执行是同一条规则（幂等）；`--remove` 删除。
执行失败（常见是没有管理员权限）时，把原命令打印出来让人复制——**不假装成功**。

**health**：响应里的 `root` 只给目录名（不给绝对路径），`files` 给白名单目录的文件数，
足以判断"对端是不是那台机器、库是不是那一份"，又不泄露路径。

## 五、证据

本机实测（Windows / 4 GB 内存小主机）：

```
$ python persona_lanbus.py serve --port 18737 --bind 127.0.0.1,127.0.0.2
绑定地址  : 127.0.0.1:18737、127.0.0.2:18737
已开始服务：127.0.0.1:18737、127.0.0.2:18737

$ netstat 核对
LocalAddress   LocalPort
127.0.0.1      18737
127.0.0.2      18737          ← 两个都真的在听

$ python persona_lanbus.py health --server http://127.0.0.1:18737
通：… /health 200 {"ok": true, "node": "<本机名>", "version": 1, "root": "…", "files": 4121}
对方节点：… · 往返 1685 ms

$ python persona_lanbus.py health --server http://127.0.0.1:18999
不通：… —— 连接被拒（服务没起，或端口 18999 没开）

$ python persona_lanbus.py firewall --allow 10.147.20.0/24
规则名  : SysPersona-LAN-8737
端口    : 8737/TCP（入站）
来源    : 10.147.20.0/24（只放行虚拟网段，物理局域网不放行）
原始命令: powershell -NoProfile -Command "New-NetFirewallRule … -RemoteAddress 10.147.20.0/24 …"
[dry] 没有改动防火墙。
```

## 六、边界

- 不在本版做"自动安装虚拟组网客户端"（ZeroTier/Tailscale 的安装与入网仍是人做的）；
- 不做"自动发现同网段节点"（扫描网段既有风险也很慢，节点地址由人指定）；
- **不做双向推送**：客户端仍只拉不推，要它干活走任务池；
- 首次接入的令牌分发仍靠"面对面/引导包"给一次，不做在线交换——这是 v6.5.0 定下的规矩。
