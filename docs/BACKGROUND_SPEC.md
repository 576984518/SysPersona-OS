# 后台处理（BACKGROUND SPEC）— v5.4

> 状态：**设计成文，未落地**。上一版 v5.3.0（保活 + 交互代理）。
> 一句话：**到线才动，不提前清；清之前先落盘。**

## 一、为什么要有这一版

上下文满不是"突然"的：它一路涨，直到某次请求被拒，才发现前面几十轮全是废料。
手动清理依赖人记得——他不该记得。所以：**监测归程序，决定归水位线，人只保留否决权。**

## 二、三档水位（同一把尺子）

| 档 | 线 | 动作 | 谁批准 |
|---|---|---|---|
| 温 | **450K** | 出接续包（已有：`persona_gauge.py --prepare`） | 自动 |
| 热 | **800K** | **先镜像**（整段会话全文落盘）再让它自己压 | 自动 |
| 断 | 请求被拒 / 超过模型上限 | 出包 + 提示换窗口 | 自动，**不改写历史** |

"满 100" 的口径沿用旧约定：每跨过 100K 整数倍提醒一次，不另立第二套计数。

## 三、四个动作

| 动作 | 做什么 | 不做什么 |
|---|---|---|
| **监测** | `hctx` 每 2 分钟读一次真实 token 用量 | 不猜、不按字数估 |
| **镜像** | 到 800K，把当前会话全文写成一份 `.md` | 不做"摘要代替正文" |
| **压缩** | 调壳自己的压缩（它认得自己的历史） | **不由我们改写历史** |
| **归档** | 镜像落 `archive\日期\`，进索引 | 不删任何原文 |

顺序写死：**监测 → 镜像 → 压缩 → 归档**。没镜像就压，等于拿记忆赌运气。

## 四、判据（三条，缺一不算成功）

1. **自然触发一次**：库里出现 `compacted=1` 且有摘要，且摘要能对上原文；
2. **镜像可读**：压缩前的全文在 `archive\` 里能逐字读出；
3. **断网回退一次**：云端不可用时，落本地/免费档，且**不丢这一轮**。

> 现状：第 1 条从未发生（从没到过线）；`compact` 在 DeepSeek 系模型上填不出嵌套参数。
> 所以这一版的验收不靠"看起来能跑"，靠**真实触发一次**。

## 五、边界

- **绝不自动删记忆**：删除永远要人点头（红线）；
- 不替用户决定"这段不重要"——压缩只压上下文，不动库；
- 只作用于当前会话的上下文，不动 `sessions\` / `archive\` 的原文；
- 失败就停：压缩失败不重试超过 2 次，改出接续包让人换窗口。

## 六、落地拆解（实现时照这个顺序）

1. `hctx` 已有 → 补「到 800K 触发镜像」；
2. 镜像脚本：会话全文 → `archive\<日期>\电脑会话\<会话id>-mirror.md`；
3. 压缩调用：走壳的接口，失败落日志，不重试超过 2 次；
4. 摘要校验：摘要里的关键实体必须能在原文里找到（防"压没了"）；
5. 托盘显示当前档位（温/热/断），红灯只在"断"时亮。
