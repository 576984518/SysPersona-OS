# 后台处理（BACKGROUND SPEC）— v5.4

> 状态：**设计成文（v1.1 补全版，2026-11-09）· 未落地**。上一版运行时 v5.3.0（保活 + 交互代理）。
> 一句话：**到线才动，不提前清；清之前先落盘。**
>
> v1.1 补的是什么：口径（两把尺子怎么合）、镜像的文件规范、失败矩阵、验收命令、压缩为什么不在本版。
> 不动的东西：三档水位、四动作顺序、三条判据、边界。

## 一、为什么要有这一版

上下文满不是"突然"的：它一路涨，直到某次请求被拒，才发现前面几十轮全是废料。
手动清理依赖人记得——他不该记得。所以：**监测归程序，决定归水位线，人只保留否决权。**

## 二、三档水位（同一把尺子）

| 档 | 线 | 动作 | 谁批准 |
|---|---|---|---|
| 温 | **450K** | 出接续包（已有：`persona_gauge.py --prepare`） | 自动 |
| 热 | **800K** | **先镜像**（整段会话全文落盘）再让它自己压 | 自动 |
| 断 | 请求被拒 / 超过模型上限 | 出包 + 提示换窗口 | 自动，**不改写历史** |

"满 100" 的口径沿用旧约定：每跨过 100K 整数倍提醒一次，不另立第二套计数。

### 2.1 口径：现在其实有两把尺子

| 尺子 | 读什么 | 谁在用 | 状态 |
|---|---|---|---|
| DSH 账本 | `%USERPROFILE%\.dsh\storages\cost-meter\ledger.json` | `persona_gauge.py`（`current()` / `level()`） | 现行；`OK 300K / CLEAN 450K / WARN 500K / HOT 700K / LIMIT 1M` |
| Hermes 库 | `state.db` 的 `turn_stats.tokens_input` | `persona_daemon.t_hctx`（120 s 一次） | 现行；`MAX 1M / LIMIT 450K / MIRROR 800K` |

**合成一条**：两个数都在时取**较大者**（保守，宁可行李早打好）；只有一个时有谁用谁；都没有就报 `unknown`，**不按字数估**。
`t_hctx` 落 `ops/hctx.json`：`{at, session, model, ctx, max, pct, level}`——这是托盘与判据的唯一读数口，别处不许再算第二份。

## 三、四个动作

| 动作 | 做什么 | 不做什么 |
|---|---|---|
| **监测** | `t_hctx` 每 120 s 读一次真实 token 用量 | 不猜、不按字数估 |
| **镜像** | 到 800K，把当前会话全文写成一份 `.md` | 不做"摘要代替正文" |
| **压缩** | 调壳自己的压缩（它认得自己的历史） | **不由我们改写历史** |
| **归档** | 镜像落 `archive\日期\`，进索引 | 不删任何原文 |

顺序写死：**监测 → 镜像 → 压缩 → 归档**。没镜像就压，等于拿记忆赌运气。

### 3.1 每一档的输入 / 输出 / 失败

```
监测：  hctx.json 读 ctx  ──►  level ∈ {OK, 温, 热, 断}
镜像：  sessions\<日期>\<来源>\*.md  ──►  archive\<日期>\<来源>\<会话id>-mirror.md
压缩：  壳接口（未接）    ──►  本版不做，见 §六
归档：  mirror.md         ──►  index\L1.jsonl 多一行（persona_index_l1.py）
```

## 四、镜像文件规范（v1.1 新增，落地时照抄）

**路径**：`archive\<YYYY-MM-DD>\<来源>\<会话id>-mirror.md`；`<会话id>` 取原文件名去扩展名，不另编新号。

**文件头**（必须逐行齐全，`blocks()` 靠它识别设备与底座）：

```
- 会话：<会话id>
- 设备：<主机名或"网页">
- 底座：<模型名，如 deepseek-web>
- 镜像于：<YYYY-MM-DD HH:MM:SS>
- 触发：hctx=<数字> / 线=<800000>
- sha256：<原文全文的 sha256>
- 原文：sessions\<日期>\<来源>\<原文件名>
```

**幂等**：同名 mirror 已存在且 `sha256` 相同 → 跳过并记一行日志；不同 → **不覆盖**，改名 `<会话id>-mirror-<HHMMSS>.md` 再写。
理由：镜像是证据，不是缓存；覆盖等于把上一份证据擦掉。

**不许做的事**：不许只写摘要、不许截断尾部、不许把 `## 用户/助手` 层级压平——压平后检索按块切不出来，等于镜像了读不到。

## 五、判据（三条，缺一不算成功）

1. **自然触发一次**：`ops/hctx.json` 里出现 `ctx >= 800000` 且同一次作业里生成了 mirror；
2. **镜像可读**：压缩前的全文在 `archive\` 里能逐字读出，且 `sha256` 与原文一致；
3. **断网回退一次**：云端不可用时，落本地/免费档，且**不丢这一轮**。

> 现状：第 1 条从未发生（从没到过线）；`compact` 在 DeepSeek 系模型上填不出嵌套参数。
> 所以这一版的验收不靠"看起来能跑"，靠**真实触发一次**。

### 5.1 验收命令（v1.1 新增；不碰真实数据）

```
# ① 干跑：强制把水位当 800K 看，只走"镜像"分支，不触发压缩
python persona_gauge.py --ctx 800000            # 期望：提示"热"档 + 打印将镜像的会话路径
python persona_daemon.py --once hctx            # 期望：ops/hctx.json 的 level 为 热，msg 带"已镜像"
# ② 镜像自证：sha256 与原文一致；重复跑一次不新增文件
python -c "import hashlib,io;print(hashlib.sha256(io.open(PATH,'rb').read()).hexdigest())"
# ③ 读得回：镜像进索引后，检索能命中，且命中带设备/底座
python persona_index_l1.py && python persona_search.py "镜像里的某个词" --k 5
```

第 ① 步用 `--ctx` 造数、第 ② 步比哈希——**判据可以被机器验**，不靠"我看着像"。

## 六、压缩：为什么本版不做（v1.1 明确）

壳的压缩接口没有稳定契约：`compact` 在 DeepSeek 系模型上填不出嵌套参数（这是实测结论，不是估计）。
**没有契约就调，等于把"压缩"写成"碰运气"。** 所以：

- 本版只做到「镜像 + 出包」，压缩**留空**，在 §十 拆解里标 `PENDING`；
- 真接的时候先做**只读探针**：拿一次压缩请求的返回体，确认字段能填满，再允许写；
- 压缩失败不重试超过 2 次；第 3 次直接出接续包，让人换窗口——**换窗口是人的动作，不是程序的补救**。

## 七、失败与降级矩阵（v1.1 新增）

| 失败点 | 现象 | 降级动作 | 告警 |
|---|---|---|---|
| 读不到账本 / Hermes 库被锁 | `ctx` 为空 | 保持上一轮读数，标 `stale`，不触发镜像 | 连续 3 次 → `ops\alerts.jsonl`（warn） |
| 镜像写盘失败（盘满 / 占用） | 无 mirror | **不压缩**，直接出包 + 提示换窗口 | error |
| 镜像成功、索引失败 | mirror 不在 L1 | 保留 mirror，下轮 `index` 作业补 | warn |
| 压缩接口不认参数 | 返回错误体 | 停手，不重试超 2 次 | warn |
| 会话文件正在被写 | 尾部半行 | 按行尾停在最后一个完整 `## 助手` 块，不写半句 | 无 |

**唯一不可降级的一条**：镜像没落盘，就不许往下走压缩。宁可这轮不压，也不能压完才发现正文没了。

## 八、容量与预算（v1.1 新增）

| 项 | 量级 | 备注 |
|---|---|---|
| 单次镜像体积 | 0.5–6 MB | 与源会话同量级，不压缩 |
| 每会话镜像份数 | 1（幂等） | 同会话跨天再触发 → 追加带时间戳的新份 |
| 索引增量 | 每份 1 行 | `L1.jsonl` 单行 < 1 KB |
| 磁盘占用 | 约等于 `sessions\` 的 1 倍 | 预留 2 倍即可，不做自动清理（删记忆要人点头） |

## 九、边界

- **绝不自动删记忆**：删除永远要人点头（红线）；
- 不替用户决定"这段不重要"——压缩只压上下文，不动库；
- 只作用于当前会话的上下文，不动 `sessions\` / `archive\` 的原文；
- 失败就停：压缩失败不重试超过 2 次，改出接续包让人换窗口。

## 十、落地拆解（实现时照这个顺序）

1. `hctx` 已有 → 补「到 800K 触发镜像」（现在 `t_hctx` 里 `HERMES_MIRROR_LIMIT` 已接 `t_export`，补的是**镜像文件规范** §四）；
2. 镜像脚本：会话全文 → `archive\<日期>\<来源>\<会话id>-mirror.md`（含 §四 文件头 + sha256 + 幂等）；
3. ~~压缩调用~~ `PENDING`：先只读探针，确认字段能填满再放开（§六）；
4. 摘要校验：摘要里的关键实体必须能在原文里找到（防"压没了"）；
5. 归档进索引：`persona_index_l1.py` 每来源一行；托盘显示当前档位（温 / 热 / 断），红灯只在"断"时亮。
