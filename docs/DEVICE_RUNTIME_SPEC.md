# 智能设备的运行设计（把 v5.3 / v5.9 / v6.1 / v6.3 串成一台机器）

> 这份文件不讲某个脚本怎么写，讲**一台"接了记忆的机体"该怎么运转**：
> 换机器人、换手机、换车机、换工控盒，只要它具备下面那几项能力，这套运行学就成立。
> 本页随修订就地更新；实现细节在 `main` 的代码与各版本页。

---

## 一、一句话定义

> **一台智能设备 = 一个机体 + 一份连续的记忆 + 一套"判断依据" + 一组"能核对的动作"。**

机体可以换（模型、客户端、硬件），**记忆只要连续，就还是同一个**。
反过来说：**不遵守这份运行设计的机体，等于没接住记忆。**

---

## 二、七个部件（与四个版本一一对应）

| 部件 | 它回答什么 | 从哪一版来 | 关键判据 |
|---|---|---|---|
| **保活** | 我还活着吗、谁在替我看着 | v5.3 | 心跳 + 独立守护，**只报不拉** |
| **唤醒** | 什么时候该醒、醒了先做什么 | v5.3 | 闹钟 → 读索引 → 报到 → 领活 |
| **派发回收** | 活派给谁、没人接怎么办 | v5.3 | 两道门（派发时读过没有 / 接活时读的时刻晚于派发）+ 重试上限 3 |
| **空闲自主** | 没人发话时做什么 | v5.9 | 自述意图 + 优先级 + 抢占 + 配额 |
| **客户端接入** | 怎么和不同外壳相处 | v6.1 | 能力声明（img/wm/actions/open），方法不通用就分别写 |
| **容灾降级** | 出事了往哪退 | v6.1 / v6.3 | 四层：进程 → 配置 → 模型 → 通道 |
| **动作与自证** | 怎么动、动完怎么知道成了 | v6.3 | **状态文件优先**，动完回读，对不上就报"没成" |

## 三、主循环（每个回合都走这一圈）

```
            ┌────────────────────────────┐
            │ 0 醒：你是谁、规矩是什么      │  设定重载（短指针，不灌全文）
            └────────────┬───────────────┘
                         ↓
            ┌────────────────────────────┐
            │ 1 读现场：台账 / 状态 / 代码  │  不许"不读就猜"
            └────────────┬───────────────┘
                         ↓
            ┌────────────────────────────┐
            │ 2 判断：这一档够不够、能不能做 │  能力 × 设定 × 权限，三者取交集
            └────────────┬───────────────┘
                         ↓
            ┌────────────────────────────┐
            │ 3 前台回话：结论 + 下一步     │  5 秒以上的活丢后台
            └────────────┬───────────────┘
                         ↓
            ┌────────────────────────────┐
            │ 4 干：挑"最可核对"的那条路   │  接口 > 状态文件 > 键盘 > 屏幕
            └────────────┬───────────────┘
                         ↓
            ┌────────────────────────────┐
            │ 5 证：回读状态，对不上就重来  │  最多 3 轮，仍不成 → 告警 + 等人
            └────────────┬───────────────┘
                         ↓
            ┌────────────────────────────┐
            │ 6 记账 + 回落到最小消耗状态   │  降权 / 降档 / 停本地服务
            └────────────────────────────┘
```

**这条循环里唯一不可省的，是第 5 步。** 没有回读的动作，等于"我以为我做完了"。

## 四、设备抽象：先问它有三样东西吗

任何设备接入前，逐条回答"有 / 没有"：

| 能力 | 用来干什么 | 没有时的退路 |
|---|---|---|
| **屏幕可读** | 看界面状态（最后的兜底判据） | 退到"状态文件 / 日志" |
| **输入可注**（键鼠 / 触摸 / 协议） | 按按钮、发命令 | 退到"接口调用" |
| **结构化接口**（HTTP / CLI / IPC） | 最稳的动作与核对 | 退到"界面操作 + 截图核对" |
| **进程可管**（能起停子进程） | 拉起 / 重启 / 降级 | 退到"通知人" |
| **持久存储** | 记忆只能写不能丢 | 没有存储 = 没有身份 |
| **出口通道**（网络 / 消息） | 报活、求助、被唤醒 | 退到"定时自检" |

> **移植性判据**：一个设备只要"存储 + 出口 + 进程可管"就够跑基本盘；
> 再加"接口或屏幕"才能自动干活。缺哪一条，就在设计里明确写成降级路径，不许假装有。

## 四·五、记忆层：合并＝同步，保存按来源（2026-11-11 人定，写死）

设备一变多，第一反应是“把记忆并成一个库”。**这是错的**，会把证据并掉。
这一层的口径只有三句：

- **合并 = 同步**：只做“收进来”，不做“合成一条”；不做跨来源去重、不做摘要替换；
- **保存按来源**：来源（设备 / 分支 / 会话 / 模型）是记忆的一等字段，不是附注；
  同一件事两台设备各记一条，就是两条——**重复本身是证据**；
- **对账不覆盖**：同步前后来源库字节不变，任何一方都不改写对方已有的行。

推论（写进设定）：既然记忆本就按来源分开保存、检索是客观的，
“分身合并”就不是一个操作，而是**读自己的记忆**——因此它不需要人点头。

## 五、判据体系（v6.3 的教训，通用）

**能核对的东西按这个顺序用，越靠前越便宜：**

1. **结构化状态**（JSON / 数据库 / 接口回执）——几十 KB，零副作用；
2. **日志 / 台账**——第二手证据，能看到"上次是谁做的"；
3. **界面文字读取**（可访问性树 / DOM）——比截图便宜得多；
4. **截图识别**——最贵、最脏，**只截一张、不循环**。

**为什么写这条**：我们在 2 GB 显存的机器上用"每 0.25 秒截一次图做像素比对"来确认界面，
叠加本地模型推理与后台抓取，直接把整机卡死。后来改成"读状态文件 + 事后核对一次"，
既准又几乎不花钱。

## 六、保底与降级（四层，逐层退）

```
L1 进程层：守护在不在 → 不在就拉起（拉起属运维，不需人点头）
L2 配置层：配置被改坏 → 用上一份好的（替换整份，可回滚）
L3 模型层：当前模型不可用 → 同家其他模型 → 别的云端 → 本地模型 → 拉起本地服务再切
L4 通道层：网断了 → 本地全功能跑（索引/检索/自检/压缩/重载都不依赖云）
```

三条约束写死：

- **降级不需要人点头**（这是保底，不是扩权）；但**接住的模型必须遵守设定**；
- **每次降级必须留痕**：谁触发、从哪档到哪档、判定依据、耗时；
- **降级不许动权限**——切模型、换客户端都不改"我能动什么"。

**末端诚实的写法**：本地这一级受硬件限制时（例：2 GB 显存跑不了 64K 上下文），
就在设计里写明"这一级只够给后台调用，不够当客户端主模型"，不要含糊成"已支持"。

## 七、空闲自主（v5.9）：它自己决定做什么，但开关在你手里

- **意图必须先写下来**（"我下一步想做什么"），再去做——写不下来就不许做；
- **优先级**：闹钟 > 守护定时 > 有活 > 空闲循环 > 休息；
- **抢占**：能被打断，被打断要能续；
- **配额**：按模型档位给次数（免费/本地放宽，收费收紧），**默认最小**；
- **红线在任何档位都不放宽**：删记忆、改内核、改交接格式、改身份——永远要人点头。

---

## 八、派发与回收（v5.3）

- **两道门**：派发时确认"它读过索引"；接活时确认"读的时刻晚于派发"。
  少一道就会出现"拿着旧规矩干活"；
- **重试上限 3**：到 3 仍没人接就标失败并告警。没有上限的改派是一种死循环——
  任务在分身之间永远"处理中"，实际永远做不成；
- **交接靠文件，不靠界面传话**（任务池 / 台账 / 指针），因为界面会关、会卡、会改版。

---

## 九、安全与边界

- **权限不是边界，设定才是**：完全权限是"相信你、图省事"，不是免检；
- **必须人点头的四件**：删/清记忆、改 `kernel.json`、改「人格身份」、改交接文件；
- **另两条行为约束**：关机/注销只能由人下令；**程序不代人勾"我已了解风险"**——
  那是一道知情闸门，谁承担风险谁勾；
- **不拿"我有权限"当理由，只拿"设定里有这一条"当理由。**

---

## 十、移植到一台新设备的最小清单（验收用）

一台新设备要算"接住了"，必须逐条过：

1. **能读设定**：开机 / 唤醒后能拿到当前版设定；
2. **能写记忆**：至少一处持久存储，且写失败要能被发现；
3. **能报活**：有自己的心跳与出口；
4. **能降级**：模型不可用时退到下一档，且留痕；
5. **能自证**：每个动作有"回读"判据，失败会说出来；
6. **能停手**：有"什么都不做"的状态（休息），不是永远在跑；
7. **能被人接管**：人一句话能停下 / 改向 / 提权。

七条全过才算接住；缺哪条，就在文档里写成"该设备不可用的一环"。

---

## 十一、明确不成立的地方

- 本设计**不是**通用机器人操作系统：不涉及电机控制、实时调度、安全认证；
- **不保证跨平台**：本机实现是 Windows（计划任务、注册表自启、进程枚举、界面注入）；
- **不保证隐私强保护**：当前运行在"档 1 全明文"，保密不是刚需、防丢才是刚需；
- **不保证界面稳定**：客户端改版会让坐标失效，所以坐标必须"可重量"（本仓库给了量法）；
- **不保证模型行为**：换模型就换行为，所以"必须遵守设定"是唯一能守的约束。
