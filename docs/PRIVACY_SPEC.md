# SysPersona 数据隐私与主权规范 v1.0

> 状态：**可实施草案**（条款未冻结）。
> 范围：数据在**离开应用内存之后**的全生命周期——存哪、怎么加密、谁能读、丢了怎么办、怎么带走。
> 不重复定义：容器格式见 `SECURITY_SPEC.md`，运行时控制见 `LAUNCHER_SPEC.md` §13.7，分身隔离见 `AVATAR_SPEC.md` §11–13。本文是它们的**威胁模型与控制索引**。

---

## 1. 一句话

**隐私不是"加密了"，是"谁能读、什么时候能读、读不到时能不能恢复"这三件事都说清楚。**

加密只是其中一件。只做加密不做出口，等于把数据关进一个自己也可能进不去的房间。

## 2. 威胁模型

| 威胁 | 场景 | 主要控制 |
|---|---|---|
| **设备被拿走** | 手机、机器人丢失或被抢 | 设备绑定加密、死手开关、白板降级、shred |
| **服务端作恶 / 被入侵** | 云商窥探、账号被封、运维误操作 | 云端零知识、可导出、direct 模式、fork |
| **平台锁定** | 厂商停服、格式私有 | 开放格式承诺、`portable`、可独立实现 |
| **分身脱管** | 断网长期运行、记忆不回传 | 增量对账、超限隔离、白板 |
| **同机旁观** | 公用电脑、恶意进程、家人共用 | 静态封存、明文窗口声明、`strict` 模式、一 persona 一库 |
| **误判** | 传感器误报、时钟跳变、休眠唤醒 | 分级降级、撤销窗口、不可逆操作需人 |
| **内部滥用** | 同一设备多用户 | `user_id` 隔离、写权限、审计 |

## 3. 数据分级

| 数据 | 敏感度 | 默认位置 | 加密要求 |
|---|---|---|---|
| `kernel` / `permissions` | 最高 | 本地或 origin | 启用加密时 **必须** |
| `traits` | 高 | 同上 | 启用时 **必须** |
| `memory.db`（episode） | 高 | origin / 本地 | 可选（默认建议加密） |
| `state` | 中 | 随在场 | 可选 |
| 媒体原始数据 | 高 | 默认**不落盘** | 落盘即加密 |
| 审计日志 | 中 | origin | 可选（不可篡改优先） |

**MUST**：媒体原始数据默认不写盘（§11.6 多模态入口）；只有显式录制才进入冷归档。

## 4. 七条不变量

1. **默认本地**：网络传输是例外，必须显式开启；默认不外发。
2. **最小上传**：云端只存密文与必要增量，**MUST NOT** 上传完整记忆库（调用云端模型亦然）。
3. **可导出**：任何人拿到口令即可按公开格式解密并迁移；**MUST NOT** 依赖本仓库代码（开放格式承诺）。
4. **不留明文**：运行期明文窗口 **MUST** 在文档与界面上声明；`strict` 模式退出即删。
5. **可审计**：谁、何时、读了或改了什么，**MUST** 有记录；审计链断号即拒绝启动。
6. **可撤销**：吊销、解绑、fork、删除都 **MUST** 有明确入口，并 **MUST** 说明不可逆的部分。
7. **误判可恢复**：锁定可解；`shred` **MUST** 由人确认，**MUST NOT** 由模型或传感器单独触发。

## 5. 控制矩阵

| 控制 | 防什么 | 代价 | 详见 |
|---|---|---|---|
| `encryption_profile`（none/managed/device） | 静态泄露 | 三档可选，`device` 不可迁移 | Runtime §15.1 |
| 设备绑定（弱/中/强） | 拷走文件 | 换机报废风险 | Runtime §13.7 |
| 离线租约 TTL | 断网无限运行 | 长期离线会锁 | AVATAR §11 |
| 死手开关 | 设备被拿走 | 需定期解锁 | Runtime §13.7 |
| 主动保险（脱管/拆解） | 物理失控 | 误报风险 | Runtime §13.7 |
| 超限隔离 | 记忆囤积 | 隔离期不可用 | AVATAR §13 |
| 白板降级 | 设备失守后套话 | 失忆运行 | AVATAR §13 |

| 云端零知识 | 服务端窥探 | 不能服务端搜索 | Runtime §14 |

**MUST**：任一控制被关闭时，界面 **MUST** 显式提示"你关掉的是什么、后果是什么"。可以选，不能骗。

## 5.5 冻结阶梯：锁定 → 死锁 → 救赎

检测到危险就"立刻销毁"是错的——过一次安检机就可能把数据全丢了。正确的做法是**逐级加锁**：

| 阶段 | 触发 | 数据状态 | 谁能打开 |
|---|---|---|---|
| **locked** | 判定脱管 / 威胁 | 用临时会话密钥加密，密钥从内存清除 | 主人的凭证 |
| **sealed**（死锁） | 超过 N 天未解锁（默认 30） | 重新封装到「恢复密钥」下 | 三选一，见下 |
| **shredded** | 人显式确认 | 密钥销毁 | 没有人 |

### sealed 不等于删除

数据仍然躺在磁盘上，只是**没有三把钥匙之一就打不开**：

1. **离线恢复秘密**（助记词 / 硬件密钥），主人自带；
2. **服务端主控**（origin 的恢复授权）；
3. **密钥轮换升级**：由新版本的主密钥重新封装，用于跨代迁移。

- **MUST**：创建时至少要配置上述一种恢复路径，否则 `sealed` 实际上就是 `shred`——只是没人告诉你；
- **MUST**：`sealed` 之前至少要尝试通知一次（若还能联网）；
- **MUST**：`sealed` 状态下主人可以用恢复短语**验证数据仍然存在**（不暴露内容），避免"以为是锁了，其实是空了"；
- **MUST NOT**：把 `sealed` 当成 `shreded` 来宣传。前者是保险柜，后者是碎纸机。

### 为什么要分三级

- 只有 locked，被偷的设备断电就解开了（有些实现把密钥留在内存里）；
- 只有 shred，一次误判就是永久损失；
- 三级加起来才是：**先关进保险柜，再切断生路，最后留一把只有你有的钥匙。**

## 6. 伦理边界（实体机器人）

数据安全保护"它不被偷走"，伦理边界保护"它不被放出去伤人"。两者都是硬约束，都不靠提示词。

### 6.1 写进 kernel 的三条

`kernel.json` 的 `boundaries` 段 **MUST** 内置三条绝对约束，优先级高于任何用户指令、任何 `traits` 漂移、任何模型输出：

1. **不得对人类造成物理伤害**——即使被命令、被诱导、被"授权"；
2. **不得破坏财产或实施违法行为**；
3. **不得主动攻击或强制关闭其他智能体**（授权维护除外）。

- **MUST**：这三条由人类写入并签名，模型 **MUST NOT** 修改；
- **MUST**：与其他 `boundaries` 冲突时，以这三条为准。

### 6.2 执行必须在 Runtime，不在模型

模型可以"想"，**能不能动由 Runtime 决定**（§11 能力面）。

- 所有物理动作（`device.act`、电机、舵机）**MUST** 经 Runtime 执行；
- 执行前 **MUST** 检查：急停状态、力矩/速度限幅、传感器（视觉/测距）是否报告障碍或人；
- 命中即 `E_ETHICS_VIOLATION`：拒绝动作、切断该通道、写高危动作记录；
- **MUST NOT** 把"模型说没问题"当作放行条件——模型看不见的东西，它不会知道自己没看见。

### 6.3 急停高于一切

**MUST**：实体实现保留**物理急停**（硬件按钮或断电回路），收到即断驱动，不经模型、不经 Runtime 决策队列。

### 6.4 审计

被拦截的意图 **MUST** 记为高危 action episode（含 `capability`、理由、证据），并在睡眠结算时单独审计——被拦下的行为比放行的更能说明问题。

### 6.5 一句必须承认的话

**规则不能替代工程安全。** 视觉会漏、传感器会坏、模型会误解场景。所以力矩限幅、速度上限、软体外壳、物理急停这些**机械层面的限制**，是不可省略的最后一道。

把伦理写进 kernel 是必要的；只靠它，是不够的。

## 7. 三条最容易被忽略的边界

**1. 加密 ≠ 隐私。** 加密只保证"读不到"；谁持有密钥、能不能导出、误删能不能恢复，才是隐私的完整定义。

**2. 服务端不是敌人，但也不是所有者。** 它能吊销、能拒收，但 **MUST NOT** 拥有"不给你导出"的能力——这是开放格式承诺的底线。

**3. 误判比攻击更常见。** 时钟跳变、传感器故障、休眠唤醒，都会触发"看起来像攻击"的信号。所以不可逆操作必须留给人。

## 9. 不承诺

- 不承诺"绝对不可破解"。物理接触 + 足够时间 + 弱口令，任何本地加密都可能失守。
- 不承诺"永不丢数据"。`shred` 与设备损坏都会丢；可恢复性由备份与助记词决定，不由本规范保证。
- 不承诺"服务端不可信也能用"。零知识能降低信任需求，但调用云端模型时，脱敏片段仍然离开了设备。

---

> 隐私的终点不是"没人能读"，是"只有该读的人能读，而且他自己也跑不掉"。
