# 成本基线（COST BASELINE）

> 一句话：**别再拍脑袋估成本了，这里有真账单。**
> 数据：DeepSeek 官方用量导出 `usage_data_2026-11-03_2026-11-09.zip`（两个 CSV，按天聚合）。

| 11-04 | **¥26.88** |

## 二、token 结构（六天合计）

| 项 | 数量 | 单价 |
|---|---|---|
| 输入 · 缓存命中 | **1,683,621,376** | ¥0.04 / M |
| 输入 · 缓存未命中 | 7,490,013 | ¥2 / M |
| 输出 | 4,945,530 | ¥4 / M |
| 请求次数 | **5,681** | — |

**缓存命中率 99.6%**——这是理解这份账单的钥匙：

- 16.8 亿 token 因为命中缓存只花了约 ¥67；
- 真正贵的是那 **749 万未命中**（约 ¥15）和输出（约 ¥20）；
- 平均每次请求：**输入 297,678 token / 输出 871 token / ¥0.0136**。

## 三、三条可以直接用的结论

1. **"每次调用带 30 万 token"是常态**，不是异常。所以压缩与索引的价值不在"省几次调用"，而在"降单次输入"。
2. **反复重试很便宜，读新内容很贵**。11-04 花掉 ¥26.88，正是新内容最多的一天；而今天（11-09）测试里烧掉的 33.8 万 token 只值几毛钱。
3. **先前的估算偏小一个量级**：我曾按 ¥0.002/轮 估算，真实均值是 ¥0.0136/次调用。凡涉及预算的判断，以本页为准。

## 四、边界

- 这是**官方导出**，按天聚合，不含每次调用的明细；
- 账单里只有 `deepseek-flash` 与 `server-tool-search` 两个条目，Shell 侧（Hermes）的调用尚未进入统计口径；
- 汇率与价格以导出时的 CSV 为准（命中 ¥0.04/M、未命中 ¥2/M、输出 ¥4/M），调价后本页数字需重算。
