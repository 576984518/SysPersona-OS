# 记忆网络（MEMORY NET SPEC）— v5.6

> 状态：**设计成文，未落地**。
> 一句话：**每条记忆都说得清"我是谁记的、从哪来、还能信多久"。**

## 一、要解决的三件事

| 问题 | 现状 | 后果 |
|---|---|---|
| **分不清谁记的** | 会话都进同一个 `sessions\`，摘要里不标分身 | 同一件事多个模型各记一遍，看起来像三件 |
| **检索没有"来源感"** | 命中只给片段 | 不知道这条是电脑会话、手机、还是网页转述 |
| **改过就说不清** | 摘要覆盖式更新 | 事后问"当时为什么这么定"，答不上来 |

## 二、分身 ID（先定名，才谈统一）

格式：`<客户端>-<模型>`，例 `dsh-v4flash`、`hermes-v4flash`、`phone-web`。

- **不取专名、只留简称**（2026-11-09 定）——模型的出厂身份已经有了，别叠加；
- 每条归档、每条索引行、每条派发记录都带 `avatar`；
- 分身之间的差异**不合并**：同一条记忆两个分身都记，就是两条，靠 id 区分。

## 三、三层可溯源（从命中一路回到原文）

```
命中片段（带 source / avatar / 时间）
  → 分索引行：这一条属于哪个来源文件（`sessions\日期\来源\*.md`）
  → 原文：逐字可读
```

判据：**任意命中，3 步之内能读到原文的那一段**，且中间不经过"再总结一次"。

## 四、统一检索（一份索引，多种来源）

- **索引一份**（全局），备份各端独立（DECISIONS 十六：统一的是索引、不是备份）；
- 检索结果按 `avatar` 标注归属，同一句话被多个分身记过 → 合并显示但**保留全部来源**；
- 冲突不仲裁：两个分身的说法不同 → 两条都留，展示时按时间排，**不挑"更对的"**。

## 五、记忆的可信度（不做分数，做时间）

不发明"重要度打分"——那会诱导人删记忆。只记三样：

| 字段 | 含义 |
|---|---|
| `avatar` | 谁记的 |
| `source` | 从哪来（会话 / 网页 / 手机 / 手动） |
| `at` | 什么时候记的（只增不改） |

"可信度"由人看时间与来源自己判断；系统不做裁判。

## 六、判据

1. **可溯源**：随便抽 10 条命中，10 条都能在 3 步内读到原文；
2. **不串味**：两台设备的同名会话不互相覆盖（按 `avatar` + 时间区分）；
3. **可重建**：删掉索引目录，能从 `sessions\` + `archive\` 重建，且命中集不缩水；
4. **不仲裁**：两个分身说法冲突时，检索仍能同时返回两条（不静默选一个）。

## 七、边界

- 不合并分身（5.4 红线：分身合并要人点头）；
- 不为"整洁"删重复：重复是证据（同一件事被两个模型独立记下，本身说明它重要）；
- 不做跨设备实时同步——同步是文件层的事（FreeFileSync / 网盘），索引只负责"读得对"。

## 八、落地拆解

1. `persona_index_l1.py` 的每行加 `avatar`（从目录/文件名推断，缺省 `unknown`）；
2. `persona_search.py` 的结果带 `avatar / source / at` 三列；
3. `persona_master.py` 汇总时按 `avatar` 分组；
4. 溯源命令：`persona_search.py --show-source <key>` 直接打印原文段落。
