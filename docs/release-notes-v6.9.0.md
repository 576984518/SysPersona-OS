# v6.9.0 · 备份不再越长越胖：三档轮转 + 没变化就不打

> **这一版只回答一个问题：为什么 3 天的备份能堆到 2 GB，以及怎么让它长期稳住？**

---

## 一、设计思想

人报的账：「3 天的会话备份现在都快 2 个 G」。查下来**不是会话长得快**：

- 每份快照都是**全量**（把 `archive` + `sessions` 重打一遍，约 170 MB）；
- 11-11 那天 20 分钟内打了 **8 份**；
- 旧逻辑只有一句「留最近 N 份」，N=8 时 8 份全量 ≈ 1.4 GB，而且**一小时内打 8 份也照留**。

所以这一版只做两件事，都不改"备份什么"，只改"什么时候打、打完留几份"：

- **没变化就不打**：源目录指纹（文件数 + 总字节 + 最大 mtime）没变就跳过整次打包；
- **按日/周/月轮转**：日留 7、周留 4、月留 3，叠两条底线——**比 7 天新的一律不删**、**最新三份一律不删**。

这两条都指向同一个原则：**备份的价值在"能回滚到某个时点"，不在"份数多"**。

## 二、步骤

```
backup.ps1
  │
  ├─① due：源目录指纹变了吗？
  │      没变 → 跳过（不产生新 zip）         ← 省的是重复的全量
  │      变了 → 打包 记忆库-<stamp>.zip
  │
  └─② retention apply：日 7 / 周 4 / 月 3 分桶
         比 min-age-days(7) 新的 → 不删
         最新三份               → 不删
         其余                   → 删，记 ops/backup-log.jsonl
```

## 三、要实现什么（目标 → 机制）

| 目标 | 机制 | 算完成 |
|---|---|---|
| 没变化不再打全量 | `persona_backup_retention.py due`（0=要打，1=跳过） | 连跑两次，第二次打印「跳过」且不产生新 zip |
| 长期份数有界 | 日/周/月三档分桶，各取最新一份 | 份数长期稳定在 7~14 份，不随天数线性增长 |
| 永不删太新的 | `min-age-days` 默认 7（**不许小于 3**） | 8 份都在 7 天内 → `plan` 显示「将删除 0 份」 |
| 至少留三个回滚点 | 最新三份无条件保留 | `plan` 的保留理由里出现「最新三份之一」 |
| 换机不再失效 | 库根：环境变量 → 脚本所在目录（含 `sessions/`）→ 报错退出 | 脚本里没有任何写死的盘符 |

## 四、细节（按职责）

**指纹**：只统计会被打进包的四类目录（`sessions` / `archive` / `memory` / `整理`），
**不**把 2.8 GB 的 `index/` 算进去（它重建即可，不是备份内容）——否则指纹永远在变，去重闸等于没有。

**分桶**：日按 `YYYY-MM-DD`、周按 `ISO 年-W周`、月按 `YYYY-MM`；每个桶只保留该桶内**最新**的一份。
分桶只决定"留谁"，**不**决定"删谁"；真正能删的还要过年龄底线与最新三份的保底。

**兜底**：机器上没有轮转脚本时，`backup.ps1` 退回老规矩（留最近 N 份），不至于一次改动把备份搞停。

**记账**：删除逐条写 `ops/backup-log.jsonl`（名字/大小/时间）；指纹写 `ops/backup-fingerprint.json`。

## 五、证据

```
$ python persona_backup_retention.py plan
现有快照 8 份 / 1398.4 MB

保留 8 份：
  记忆库-20261112-1123.zip   231.9 MB  最新三份之一
  记忆库-20261111-1145.zip   171.6 MB  最新三份之一
  记忆库-20261111-1138.zip   169.1 MB  最新三份之一
  记忆库-20261111-1136.zip   168.6 MB  太新（< 7 天），不删
  …（其余同理）

将删除 0 份 / 0.0 MB
  （没有可删的：都还在年龄底线内，或在保留档里）

$ powershell -File backup.ps1        # 指纹刚记录过，再跑一次
源目录没有变化，跳过本次备份（要强制打：加 -Force）
退出码 0；备份目录里 zip 数量仍是 8
```

**这说明**：那 8 份（1.4 GB）现在一份都不会被删——它们全在 7 天底线内；
真正开始瘦身是在第 8 天起，按日/周/月三档逐步落到 7~14 份。

## 六、边界

- **不改**"备份什么"：还是正文 + 归档 .md + 宪法级几份 + memory 文本，密钥/凭据仍然排除；
- **不做**增量包（增量意味着"少一份就链式失效"，可靠性换体积，不划算）；
- **不做**自动传到别处（第二份备份仍在另一块盘，由既有的 `backup2` 任务负责）；
- 年龄底线**不许小于 3 天**（写死），要更激进得人手动删。
