# v6.11.0 · 清债：本机字面量归零 + 位置解析收成一个模块

> **这一版只回答一个问题：公开仓库里，能不能做到"一行本机路径都没有"，同时不把任何一台机器的行为改坏？**

---

## 一、设计思想

仓库里长期躺着几类字面量：`D:\` 开头的库根、某台机器的 `ProgramData`、某个用户名下的壳 exe、
一台 NAS 的 UNC 路径。它们**在这台机器上能跑**，所以一直没被发现——但每一条都是"换机必错"，
而且公开仓库里带着别人的机器路径本身就不合适。

清这类债最容易犯两个错：一是**边清边改行为**（顺手重构，结果没人能判断哪里变了）；
二是**把"没有"当成"猜一个"**（探不到就塞个默认值，错误被藏起来）。

所以这一版只做两件事：

- **只替换位置来源，不改任何逻辑**：所有字面量换成 `persona_locate` 的解析，函数签名与调用方式一个不动；
- **解析顺序固定且不猜**：环境变量 → `persona_root`（唯一出口）→ 由标准环境变量推出的默认位置 → **空串**。

## 二、步骤

```
每个位置都按同一顺序回答"它在哪"：
  ① 环境变量（人显式设的）
  ② persona_root（已处理变量/本机配置/多盘探测）
  ③ 标准环境变量推出的默认位置（%LOCALAPPDATA% / %PROGRAMDATA%）
  ④ 都没有 → 空串，让调用处报一句清楚的话（绝不塞一个"看起来能跑"的值）
```

## 三、要实现什么

| 目标 | 机制 | 算完成 |
|---|---|---|
| 仓库里没有本机字面量 | 全局替换 `D:\…` / `C:\Users\<用户名>` / `\\Nas-…` / 旧库根 | 非注释行扫描命中 0 |
| 换机器不改行为 | 同一台机器上替换后，`persona_locate` 解析出的值与原来字面量一致 | `python persona_locate.py` 六项全部解析到真实位置 |
| 不自伤 | 全部 `.py` 重新编译；`selftest` 全绿 | 编译失败 0；`PASS 36 / FAIL 0` |
| 位置解析只写一份 | 新增 `tools/ctxpack/persona_locate.py`（`vault/runtime/node/dsh_exe/hermes_home/hermes_exe/mirror`） | 各脚本只调它，不再各自拼路径 |

## 四、细节

**为什么单开一个模块而不是塞进 `persona_root`**：`persona_root` 是"路径解析的唯一出口"，
但它要求调用方把**上下文**（是库根、是运行时、还是客户端家目录）说清楚；
这批脚本要的恰恰是"你给我一个能用的值就行"。把"就地方便"和"严格出口"分开，
既保住了 `persona_root` 的克制，也不必让每个小脚本写五段兜底。

**替换是字面量级的**：用逐条 `str.replace`（单反斜杠，与文件内容完全一致），不写正则，
28 个文件一次替换完，避免"正则手滑把代码改坏"。只要文件里出现 `_loc.`，就补一行 import。

**没有顺手改逻辑**：`ROOT` 还是 `ROOT`、`HOME` 还是 `HOME`、`DB` 还是 `DB`，
只是右边的值从字面量变成了解析调用。行为差异只可能来自"探不到"——而那正是我们要的：**报错，不猜**。

## 五、证据

```
$ python persona_locate.py
runtime      <运行时>
node         <运行时>\node\bin\node.exe
dsh_exe      <壳的 exe>
hermes_home  <Hermes 家目录>
hermes_exe   <Hermes 桌面端 exe>
mirror       （没有：不猜）          ← 未设 SYSPERSONA_MIRROR，就老实说没有

$ 非注释行扫描 'C:\Users\|D:\|\\Nas-1900|NAS-1900'
（命中 0 行）

$ 全树编译（两个仓库根、两百多个 .py）
编译失败数：0

$ python selftest.py
== 结果：PASS 36 / FAIL 0 ==
```

替换规模：**28 个文件**（库 `脚本/` + 仓库 `tools/`），全部改动都是"值的来源"，无一处改动逻辑。

## 六、边界

- 这一版**没有**做完 B85 的全部：`_read_json` / `_write_json` 这类小工具在七八个文件里各有一份，
  合并它们要动**加载顺序与异常语义**，风险比这次高，留到下一版单独做；
- `persona_locate` 不判断"路径是否有效"（存在性检查留给调用处），
  这样它能被用来回答"该往哪找"，而不会因为文件暂时不在就返回空；
- 不改任何配置文件格式、不改任何数据文件；
- 文档里的历史路径**不动**（那是记录，不是代码）。
