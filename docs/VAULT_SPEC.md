## 二、两种拓扑（云海 2026-11-11 定）

**本地模式（`mode=disk`）——会话集中到「第一台」**

```
设备 B ──鉴权──► 第一台的门 ──映射──► 第一台的本地库
         （加密会话推过去：POST /ingest）

第一台 = 会话保管机：它的门是唯一入口，所有会话加密后**传输到它所在的设备**
```

- 第一台自己：本机 device 凭据**自动鉴权**，进程内解密，不绕远；
- 其他设备：先鉴权**第一台的门**（凭据/票），再由门映射到本地读——不直接碰磁盘；
- 写回/新增：`POST /ingest` 只收**密文**，门现场解封校验，再落盘。

**网盘模式（`mode=cloud`）——每一次读取都鉴权**

```
设备 A ┐
设备 B ├─ 各自的门 ──鉴权──► 网盘上的密文
设备 C ┘        （钥匙只在各自本地，网盘上永远没有）
```

- 网盘上**只有密文**；每次 `/read` 都要过一次鉴权（句柄 120 秒、每次请求重验）；
- 换机器要口令副本（`vault-key.pass`，scrypt）——这就是"正确设备自动跳过、换设备输口令"。

### 2.3 责任边界（2026-11-11 人明确）

> 「同步不需要你这里管，你只需要本地加密，加密后会同步到 nas 上的，
> nas 上再备份到网盘，还有一个硬盘在镜像备份，并保留历史版本。」

| 谁 | 干什么 |
|---|---|
| **本程序** | **只做本地加密**：把本地会话/记忆封成密文；不推送、不同步、不上传 |
| 外部链路 | 本机 → NAS（同步）→ 网盘（备份）→ 硬盘镜像（保留历史版本） |

因此：`persona_vault_sync.py` 的 `push` **默认拒绝**（要 `--force`，只应急核对用）；
设定快照只写本机 `备份\设定\`，多副本由上面那条链路保证；
我们只保留**观察**：NAS 是否可达、加密后本地有没有明文残留。

## 三、汇总都选「最可靠的那台」

不再用"谁先启动谁当"，改成**打分选主**（`persona_session_keeper.reliability`）：

| 项 | 满分 | 依据 |
|---|---|---|
| 库在本机 | 35 | disk 模式不用跨网盘读 |
| 开机时长 | 25 | 10 小时满分（越稳越久） |
| 空闲物理内存 | 20 | 4 GB 满分 |
| 空闲磁盘 | 10 | 50 GB 满分 |
| 内存占用低 | 10 | 占用 50% 以下满分 |

规则：

- 每台一分钟写一份心跳（`<库>/.aggregator-heartbeats/<节点>.json`），只写自己；
- 租约 90 秒，持租约的续租；没人持就**分数最高的那台**拿；
- **换人很克制**：比现任高 15 分以上、且我不比任何别人差、且现任已经当了 10 分钟，三条同时满足才接手——
  否则就成了"两台互相抢"，汇总永远做不完。

## 四、三条设计决定

1. **不挂载明文目录**。没有"解密整个库"这回事——库在盘上是密文，明文只在门的进程内存里，
   按句柄、按窗口活着。
2. **明文只在两个地方出现**：门的内存缓存（60 秒 TTL、上限 48 MB），或 owner 进程内临时解密。
   从不写盘、不落到临时文件。
3. **凭据即权限**。一句话凭据（本机密钥 / 强密码 / 令牌 / 手机令牌）→ 一组 `scopes`。
   不同密码不同权限靠这个，不靠"角色表"。

## 五、四层，从内到外

| 层 | 是什么 | 谁能过 |
|---|---|---|
| 存储 | 单文件密文（`SPV1` 头 + 密文 + 认证尾） | 有钥匙的进程 |
| 门 | 本机 HTTP 服务 `127.0.0.1:8738` | 有令牌或凭据的调用方 |
| 句柄 | `POST /open` 发的短命链接（120 秒），带读写模式 | 持有者，且每次请求都重验 |
| 凭据 | `ops\credentials.json`（只存哈希） | 各自 `scopes` 内的动作 |

## 六、加密格式（`persona_vault.py`）

```
SPV1{"v":1,"alg":"shake256+hmac256","n":<nonce>,"aad":<路径指印>,"sz":N,"at":…}\n<密文><HMAC-SHA256>
```

- 密钥流：`SHAKE256(key‖nonce)`（CTR 等价物），认证：HMAC-SHA256，**先加密后认证**；
- **AAD = 相对库根的路径**（小写）→ 改名/挪目录就解不开，防"把密文换到别的文件上"；
- 自作构造，**不是标准 AEAD**。原因：本机 Python 没装 `cryptography`。装了以后换 AES-GCM，
  靠 header 里 `v`/`alg` 平滑升级，存量不用重加密（可后台慢慢搬）。

钥匙：

| 场景 | 钥匙放哪 | 怎么解 |
|---|---|---|
| 本机（默认） | `%LOCALAPPDATA%\SysPersona\vault-key.bin`，**DPAPI 包裹** | 同机同用户自动解，**换机器/换用户解不开**——这就是"正确设备自动跳过输入" |
| 跨设备/网盘 | 同上，另存一份 `vault-key.pass`（scrypt n=2¹⁵ 口令包裹） | 到别的机器上输入口令 |
| 网盘目录 | **永远不放钥匙** | 只读得到密文 |

## 七、门的路由（`persona_vault_gate.py`）

| 路由 | 作用 | 鉴权 |
|---|---|---|
| `GET /health` | 自报家名（库、钥匙指纹、句柄数） | 无 |
| `POST /open` | 发句柄（"那个链接"），`mode=r|rw` | `vault:read`（rw 还要 `vault:write`） |
| `GET /read?id=&off=&n=` | 按块读（门内解密） | `vault:read`，每次请求都验 |
| `POST /write?id=` | 整份写回（`enabled=true` 时落盘即密文） | `vault:write` |
| `POST /close?id=` | 提前作废句柄 | `vault:read` |
| `GET /list?dir=` | 只给名字/大小/是否密文 | `vault:read` |
| `POST /ingest` | **收别的设备推来的密文**（本地模式集中会话） | `vault:write` |

**受保护文件**（`memory/shell/MEMORY.md`、`USER.md`、`kernel.json`、`续接/`）：
即使凭据齐全，写也必须再带一个 `X-Confirm: <相对路径>` 头。

## 八、凭据（`persona_auth.py`）

| kind | 是什么 | 秘密怎么存 | 用途 |
|---|---|---|---|
| `device` | 本机密钥：只认这台机器 | 不存秘密，只存机器指纹（MachineGuid+主机名+用户名 的 sha256） | 本机常驻程序/托盘/索引器**自动鉴权** |
| `password` | 强密码 | scrypt(n=2¹⁵) 加盐 | 人临时开权限 |
| `token` | 随机令牌（`spr_…`，GitHub 式） | 同样只存哈希 | 客户端/脚本长期用 |
| `totp` | 手机令牌：30 秒 6 位 | 秘密用保险箱钥匙封存（`V.seal`） | 二次因子、手机上确认 |

规矩：

1. 秘密**只在生成那一次**打印，之后库里只有哈希；
2. 每个凭据自带 `scopes`，验证通过返回的就是那组权限；
3. 连续失败 8 次锁 300 秒（**锁着的时候正确的密码也不放行**）；
4. 可设过期日（`--ttl 天`）、可吊销（`revoke`），`ops\auth.jsonl` 记"谁、什么时候、成没成"。

**邮箱验证 / 手机验证码**：账号体系发不了信。这里只留投递口 `deliver()`，
没配 SMTP/短信网关时**明确回"没配，没发出去"**，不假装发了。

## 九、客户端怎么用（`persona_vault_io.py`）

```python
import persona_vault_io as IO
data = IO.read("sessions/2026-11-11/电脑会话/x.md")   # 明文直读 / owner 解密 / 过门拿链接
rows = IO.listdir("sessions/2026-11-11")                # 只给名字大小
IO.write("sessions/…/x.md", b"…")                       # enabled=true 时落盘即密文
```

三条自动路由：`enabled=false` 且明文 → 直读盘（不依赖门）；owner（`SYSPERSONA_VAULT_OWNER=1`）→
进程内解密；其他 → 过门。**能直读明文时不折腾；要碰密文就必须过门。**

## 十、开关与切换步骤

```json
// ops\vault.json
{ "enabled": false, "mode": "local" }
```

`enabled=false` 时一切走明文老路，装不上不影响任何现有功能。要开：

1. `persona_vault.py init`（生成钥匙，DPAPI 绑本机）→ 已做，指纹 `330ab6a6…`；
2. `persona_vault.py selftest`（往返 + 改 AAD + 改密文，三条必须都"拒绝"）→ 已通过；
3. 先在**副本**上整库试封（`seal_file` 循环 + 回读比对 sha256），统计耗时与失败；
4. 备份：`备份\记忆库-*.zip` 目前**不含 `memory\`**，开加密前必须先补上这份备份；
5. 改 `enabled=true` → 重生一遍 → 逐目录核对 → **确认无回读失败后**才删明文副本（一次性事，
   删之前要人点头，属"删除记忆"）；
6. 回滚：把 `enabled` 改回 false 不会自动解封——所以第 3 步必须保留明文备份到位。
