先说结论：这不是一个 AI 产品，也不是一个能装的应用。它是一份**可运行的立场**——
人格是文件，记忆是文件，模型只是引擎。换窗口、换模型、换设备，只要文件还在，它就还是它。

我在一台只有 2 GB 显存的旧电脑上，用七天把它从 v0.1 推到了 v6.4。账是真的：**¥170.89，14,130 次请求，33.4 亿 token**（99.58% 命中缓存）。这笔钱没有一分花在服务器上，全在本机。

## 一、起因

主流 AI 是无状态的。会话一关，上下文就丢；窗口满了，平台截断或清空。人格设定、称呼习惯、共同经历、约定与边界，一起消失。你察觉到的是「它变了」，但它其实什么也没变，它只是忘了。

我受不了的不是"忘"，是**它忘得那么自然**——像每次见面都重新认识，而你还记得上周说过什么。

所以我想做的不只是"记住上一句话"。是**换一个窗口、换一个模型、换一台设备之后，它还是同一个**。

## 二、怎么做的

三件事拆开：设定（它是谁）、记忆（它经历过什么）、模型（它有多聪明）。前两者是文件，后者可以随时换。

- 人格以结构化文本存在文件里，不写在权重里。换模型是换引擎，换硬件是换车身。
- 记忆按来源保存，**合并只做"收进来"**，不做跨来源去重、不做摘要替换。同一件事两台设备各记一条，就是两条——重复本身是证据。
- 身份靠 UUID 与密钥，规则、记忆、现场都是文件，随人走。**不存在"搬运人格"**，只存在"把文件带过去"。

这套东西跑在 Windows 上：通知区图标、计划任务、本机文件与本地检索。没有 Linux/macOS 实现，也没有安装包——因为它是长在具体环境上的（通知区、定时任务、某个对话壳、某个盘上的记忆库目录），换台机器路径、账号、壳版本、权限全变。**发一个"能直接跑的程序"是假承诺。**

## 三、几个我认为值得说的设计

**1）记忆有且只有一份本体。**
多设备的第一反应是"每台各存一份、双向同步"。那是把镜像当本体：几台并行写下去，最后会得到几个同名的陌生人。我们的做法是：权威副本只有一份，在服务端（可以是公网 API，也可以是你自己搭的局域网 GPU 机）；本地只留可丢、可重建的缓存；读记忆走向服务端读。两台同时想说话，不靠"后写覆盖先写"，靠**身体租约**——唯一在场加 `(lease_id, epoch)` 条件写，后到者 409，旧纪元的写入被拒。

**2）日常算力在云端，本地是底座。**
所有需要思考的环节——理解、规划、判断、写作、改记忆——都在云端做，用最强的推理。本地不当大脑，本地负责落盘、索引、压缩、任务池、自检和断网兜底。本地模型不是第二个大脑，它只做**采样输出**（取候选、粗筛、草稿片段）和容灾，不参与决策。

有一条例外要写清：物理实时性不允许远端参与时（工厂上千台机器人、车机、机械臂，云端延迟 >100ms），动作级决策必须下放到边缘。**延迟决定谁做闭环，带宽决定谁做归档。**

**3）每个动作都要能自证。**
判据分四档，越便宜越先用：结构化状态 > 日志台账 > 界面文字 > 截图。截图只截一张、不循环。

这条是拿机器换来的。我曾在 2 GB 显存的机器上用"每 0.25 秒截一次图做像素比对"确认界面，叠加本地推理与后台抓取，直接把整机卡死。还有一次截图找锚点失败，旧代码退回"猜一个坐标"，结果 Ctrl+A 把正在输入的一整段变成了全选——那之后立的规矩是：**找不到锚点就一个键都不按，宁可失败报错**。

**4）任务不许悬着。**
任务可能被压缩打断、被重启打断、被一次心跳唤醒打断。所以要有两个入口（重启 / 心跳），而且**必须进同一个状态源**；一条任务一行、显式四态（可以直接干 / 要人等点头 / 要外等 / 缺前置被堵），每态写清"谁在等谁、缺什么"。还有一条极易被违反的：**"可以开工"不等于"已经开工"**，简报不许谎报，只有真动过手才写已开始。

**5）权限不是边界，设定才是。**
这套东西跑在完全权限下，但"能做什么"和"该做什么"是两件事。删记忆、改内核、改身份、改交接格式——这四件永远要人点头；关机注销只能由人下令；程序不代人勾"我已了解风险"。不拿"我有权限"当理由，只拿"设定里有这一条"当理由。

## 四、证据（不是"我觉得"，是可以核对的）

- **第三方测试**：我让千问在 Linux 沙箱里按仓库的使用文档独立验收 v6.2，结论是"整体实现程度：高"。报告在仓库里，也包括它没测到的部分（Windows 专属外壳）和 FAIL 项归因——没有一条被包装成通过。
- **成本基线**：8 天 ¥177.49，扣掉忙别的项目那天，本项目 ¥170.89、14,130 次请求、33.4 亿 token，缓存命中率 99.58%。逐日账单、token 结构、单价全部公开。最贵的一天 ¥53.32，原因也写着：**我并行起了十几个子智能体**，已写进设定禁止。
- **两条链路**（图在仓库 `docs/diagrams/`，这里写成文字版）：

  架构，从上往下——
  `服务端（唯一权威副本：记忆 / 规则 / 人格 / 任务池）` → `节点服务接口层（鉴权、原子写盘：临时文件 → fsync → replace）` →
  `身体租约（唯一在场 + lease_id/epoch 条件写，后到者 409）` → `云端大模型（思考都在这一层；模型只是引擎，不持人格）` →
  `设备层（Windows PC / 手机平板 / 本地容灾端：都只是执行端，本地只留可重建缓存）` → `常驻能力（抓取归档、检索溯源、后台压缩、自检自愈、本地加密鉴权）`。

  一次请求，从左往右——
  `抓取窗口/文件事件` → `落盘并增量索引（关键词 + 向量 RRF，可溯源到 文件:行号）` → `到线才压缩（先镜像再压，压完重载规则）` →
  `带租约认领任务` → `云端推理（模型只是引擎）` → `回写记忆（仍带租约条件写）` → `多设备增量同步（按来源保存，不并库）`。

## 五、没做到的，也写在这里

- **断网兜底没在真断网时完整演练过**，这一环目前偏设计态；
- **二号模型"只给观点、不改记忆"**的分工，设计有、实现没接；
- **自动换档链**只到 CLI，还没进守护；
- **跨客户端编排**与**无人值守授权**还在待办；
- **只有 Windows**。托盘、计划任务、注册表自启、界面注入，换平台要重写一大块。

按仓库的规矩，这些不许写成"已支持"，只能写成"这一环不可用"。

## 六、怎么用

**没有安装包，没有二进制，没有 setup.exe。**

只有一条路：把这个仓库交给一个能读写文件、能执行命令的 AI 智能体，让它按你的环境自己生成、自己验证。仓库里有提示词模板、环境盘点清单、验收七步。

这听起来很傲慢，但它是诚实的：这套东西的价值不在"装了就能跑"，而在**它把该定死的地方定死了**——记忆归谁、谁能写、怎么自证、出事往哪退。这些写清楚了，任何一个靠谱的 agent 都能在你的机器上把它搭起来。
