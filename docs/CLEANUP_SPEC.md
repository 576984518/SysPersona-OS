# 清理：先搬后删（CLEANUP SPEC）— v6.7.0

> **这一页只回答一个问题：怎么清垃圾，才能既腾出空间、又永远不出现"删错了拿不回来"？**

---

## 一、要解决的三件事

1. **"删除"是不可逆的**：一次误判就是永久损失，而清理跑在后台、没人盯着。
2. **清理不能实时**：频扫会跟正在写的进程抢文件，也会把"刚生成、正在用"的临时文件当垃圾。
3. **空间要真腾出来**：只搬不删等于把垃圾换了个位置，磁盘并没多出来。

## 二、两段式：先搬进筐，过几天再真删

| 段 | 干什么 | 后果 |
|---|---|---|
| **第一段 `sweep`** | 把"够老"的白名单垃圾**移动**到 `清理/待删/<批次>/`，保留原相对路径，逐条写清单（原路径 / 大小 / sha256 / 存留天数 / 为什么算垃圾） | **一个字节都不删**，随时可整批还原 |
| **第二段 `purge`** | 筐里放满 `keep-days`（默认 7）天的批次才真删，删除前再写一遍日志 | 空间真正回收 |
| **随时 `restore`** | `restore --batch <批次>` 把那一批整批搬回原位；**不覆盖**已存在的文件，冲突逐条报出来 | 误删的代价 = 一条命令 |

**关键取舍**：宁可多占 7 天磁盘，也不做"当场删除"。误删的代价从「不可逆」降到「一条命令」。

## 三、什么时候才叫"够老"

| 闸 | 默认 | 为什么 |
|---|---|---|
| 年龄闸 | `min-age-days = 7`（**不许小于 3**） | 正在写的临时文件会不断刷新 mtime；7 天没人碰才是真垃圾 |
| 时段闸 | 只在**凌晨 4 点以后**动手 | 夜里没人用机器，搬大文件不跟人抢盘 |
| 频率闸 | **一天只真动手一次**（日期闸） | 不做实时清理；重启也不重复干 |
| 体量闸 | 单次 > **500 个文件** 或 > **2 GB** 就停 | 停下并写 `ops/janitor-stop.json`，要人 `--force` 才继续 |

## 四、什么样的文件才算垃圾（白名单，宁少不多）

收：`*.tmp` · `*.tmp.<十六进制>`（调度租约那种） · `*.partial` · `*.crdownload`

**永不收**（写死在代码里，不靠人记得）：

- `.git/` 与 `清理/` 自身；
- `vectors.npy` / `meta.jsonl` / `fts.db` / `*.db` / `*.zip` / `*.safetensors` / `*.gguf`
  ——即使名字长得像临时文件；
- `.bak-*` 这类"修改前备份"（它们是旧版本，不是垃圾，要不要清是另一个决定）。

## 五、命令

```bash
python persona_janitor.py status                 # 只读：现在有几个候选、筐里几批、各多大、上次什么时候扫的
python persona_janitor.py sweep --dry            # 只看会搬什么（默认就是 dry）
python persona_janitor.py sweep --apply          # 真搬进筐
python persona_janitor.py purge --apply --keep-days 7   # 只删放满 7 天的批次
python persona_janitor.py restore --batch <批次> --apply
```

后台由守护进程的 `janitor` 任务调用 `daily`（每小时看一次，按上面三道闸决定是否动手）。

## 六、判据

| # | 造一个场景 | 期望 |
|---|---|---|
| 1 | 造一个 10 天前的 `probe.tmp` | `sweep --apply` 把它搬进筐，原处消失，清单里有一条 |
| 2 | 紧接着 `restore --batch <批次> --apply` | 文件回到原位，内容一致 |
| 3 | 造一个 1 小时前的 `new.tmp` | `sweep` **不动它**（年龄闸） |
| 4 | 筐里的批次不满 7 天 | `purge` **什么都不删** |
| 5 | 把 `--min-age-days 1` | 直接拒绝（退出码 2），提示不能小于 3 |
| 6 | 一次候选超过上限 | 停下并写 `ops/janitor-stop.json`，不删任何东西 |

## 七、边界

- **不动**备份压缩包（`备份/*.zip`）的保留策略：那是"删备份"，比删临时文件敏感，要单独定；
- **不动**索引本体（`vectors.npy` / `meta.jsonl` / `fts.db`）：索引可重建，但重建很贵，不由清道夫决定；
- 不做"按扩展名批量清"的通用模式：只认白名单，避免一次配置失误清掉整个目录；
- 不做跨盘/跨节点清理：清道夫只管本机这一个库根。
