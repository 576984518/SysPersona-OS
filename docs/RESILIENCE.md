# 容灾与降级 — RESILIENCE

> 状态：**v6.1 成文**（2026-11-11）。前几版散落在 `BACKGROUND_SPEC`（压缩与落盘）、
> `INTERACT_SPEC`（保活）、`TRAY_SPEC`（异常可见）里，这一版收成一条线：
> **出事时先保通路，再保质量，且降级必须看得见。**
> 说明：容灾（dr）的自动切换默认**关着**，只做了判定与记账——"没做完的东西不假装做完"。

## 一、三条原则

1. **先保通路，再保质量**。能说话比说得好重要；能挂上去比模型强重要。
2. **降级必须可见**。任何换档（模型/壳/通道）都要留痕并自报 `[非主档：<模型>]`，不许悄悄降。
3. **只有在断网也能跑的东西，才算容灾**。要联网才生效的"备用方案"是画饼。

## 二、四层，逐层降

| 层 | 坏成什么样 | 我们怎么接住 | 现在到哪 |
|---|---|---|---|
| 进程层 | 客户端窗口关了 / 内核死了 / 网关掉了 | 各自判活 + 拉起；网关独立进程，每分钟一轮 keeper | ✅ 在用 |
| 配置层 | 改配置改坏了，起不来 | 好档快照（`config-good`）+ 回滚；流水线 杀→备→换→起→验→失败回滚 | ✅ 在用 |
| 模型层 | 主模型不可用（余额/限流/断网） | 备用链：本地 Herdsman → 硅基流动 → DeepSeek 官方；切换 = 换一份配置文件 | ⚠️ 手动为主 |
| 通道层 | 电脑不在 / 断网 / 只有手机 | 微信代班（Hermes 通道）；断网代班卡落文件 | ✅ 在用（代班卡） |

## 三、模型层：降级链怎么排

```text
paid    DeepSeek 官方（主档；能力最全，最贵）
  ↓ 余额 < 阈值 或 连续失败
cloud   硅基流动（便宜；DeepSeek-V4-Flash / Pro 可选）
  ↓ 同样条件
local   本机 Herdsman（127.0.0.1:8080，Qwen 系；断网也能跑，能力弱、要显存）
```

- 判定：余额（DSH 侧读账本；硅基侧读页面快照）+ 连续失败计数；
- 动作：**换一份可替换配置文件 + 一行命令**，不点界面、不改注册表；
- 可见：切过去之后必须自报 `[非主档：<模型>]`，界面上能看出"现在不是主档"；
- 门槛：换底座模型要人点头（内核级决定，不做成自动）。

**余额阈值（这台机器的口径）**：DeepSeek < ¥5、硅基 < ¥1 时触发降级；同一档不反复横跳（有冷却）。

## 四、通道层：断网代班

- 微信侧（Hermes 网关）保持常开：网关是独立进程，桌面重启不会带上它，所以单独守（`gateway status` 判活 + VBS 隐藏拉起）；
- 断网时落一张**代班卡** `ops/hermes-relay.md`：当前在办、下一步、谁写的，网络恢复后自动移除；
- 手机入口只认白名单命令（`check` / `dr` / `request local|cloud|paid` / `rollback`），拒绝拼接；
- 电脑整机关掉时，手机这条线就是全部——所以网关存活优先级高于一切界面操作。

## 五、判定与动作分离：`dr-plan.json`

- 规则和"条件→动作"的对应关系全在配置文件里，后台程序只负责读它、按表触发**预建好的任务**；
- 为什么要预建：断网时没法现建任务，只能跑已经存在的；
- 开关（`enabled`）关着时**只判定、只记账、不动手**——这就是现在的默认状态。

## 六、恢复顺序（别乱）

```text
1 网关（微信线）  → 2 内核（:9120 health）  → 3 桌面窗口  → 4 重读设定（让它把规矩装回来）
```

顺序反了会怎样：先开窗口后起内核，窗口会连不上、显示一堆红；先重读设定后起内核，那句话根本发不进去。

## 七、开关（七组，默认只开六组）

`dr`（容灾自动切换，**默认关**）、`hermes`、`backup`、`maint`、`ctx`、`deepseek`、`handoff`。
`dr` 关着是诚实的：容灾判定和记账在跑，**自动换档没做完**。

## 八、已知风险（写在这里，免得被当成"已完成"）

1. 模型自动换档只做到"判定 + 提示 + 一键换配置"，没有做"无人值守自动切"；
2. 硅基余额靠页面快照，登录态过期就取不到（会显示成"读数不可用"，不冒充正常）；
3. 客户端升级（内核/桌面版本变化）可能让某个操作方法失效——托盘会报"版本变了，可能要同步"，但适配要人做；
4. 断网代班依赖 Hermes 网关进程活着；网关和桌面一起崩时，只能等看门狗或人。

## 八点五、设定文件不许只有一份（v6.2 新增）

人 2026-11-11：「每一个设定文件都不能只有一份……这些全部都按同样的逻辑备份。」

对象：`memory\设定\*.md`、`memory\shell\{MEMORY,USER}.md`、`memory\MEMORY.md`、
`续接\接续包-最新.md`、`DECISIONS/BACKLOG/SKILL/HANDOFF/state`。
逻辑照交接文件那套——**定时、快照不可变、分级保留**：

| 项 | 值 |
|---|---|
| 频率 | 2 小时一次（守护任务 `settings`） |
| 位置 | **两处**：本机 `备份\设定\` + 网盘 `\\Nas-1900\nas-文件\AI会话检索记录\备份\设定\` |
| 快照 | `<stamp>\` 目录 + `manifest.json`（每份 sha256）；另存 `最新\` 供体检比对 |
| 保留 | 48 小时内全留 → 每天 1 份留 60 天 → 每周 1 份留 365 天 |
| 排除 | 名字像密钥的（`*secret*`、`*.key`、`*.dpapi`、`*token*`）永不上网盘 |

**体检进日常检查**（守护任务 `backed`，半小时一次，四项）：
① 记忆库 zip 最新不超过 36 小时；② 设定快照两处齐全、哈希一致、不超过 26 小时；
③ 网盘密文不比本地少太多；④ 钥匙在本机、网盘上没有。
任一项不过 → 托盘变琥珀。

## 九、判定"接住了"的最小证据

- 进程层：托盘红→绿，日志里有拉起记录；
- 配置层：回滚后 `check_config_valid` 通过、客户端能起；
- 模型层：`[非主档]` 出现过且能正常答话；
- 通道层：手机发一条，微信里收到回复（延迟记在案）。
