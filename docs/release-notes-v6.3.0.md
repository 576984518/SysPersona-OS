## 一句话设问

**当我不坐在电脑前，它能不能替我把"界面上的那几个开关"扳到该在的位置——而且每次都说得清它扳了什么？**

## 设计思想

前三版解决的是"它自己怎么活"（后台、客户端契约、本地加密）。这一版解决另一件事：

> **客户端的界面是它唯一的操作台，而界面没有对外的 API。**

DeepSeek Harness 只在界面里提供「换模型」「推理档位」「权限档」这几个开关：没有斜杠命令能换档位，
权限档还带一个必须人勾的风险确认。要让它无人值守地活下去，就必须能操作界面——
但**"能用鼠标点"是最危险的一种能力**：点错一格就可能是把权限开到最大。

所以这一版守三条：

1. **先能判断，再能动手**：每个开关先用**状态文件**读出"现在是什么"，再算"要按几下 / 点哪一行"；
2. **动完必须自证**：每一步之后回读状态（`pending.model` / `pending.reasoningEffort` / `permissions.preset`），
   对不上就报"没成"，不写"已完成"；
3. **有些门不许程序替人推开**：权限档的知情确认、把推理档切到 `off`、删记忆这类，一律留给人。

## 步骤

```
读状态（会话缓存的 modelSelection / permissions）
        │
        ├─ 推理档：算出目标在第几行 ──┐
        ├─ 模型  ：/model 回车开列表 ─┤
        └─ 权限  ：点开权限栏 ────────┘
                                      │
                        点/按（以"蓝色发送按钮"为锚点定位）
                                      │
                          等 1 秒 → 回读状态核对
                                      │
                     ┌────────────────┴────────────────┐
                  对上了                            没对上
                     │                                 │
                记一行账本                      关掉下拉、重来一次（最多 3 轮）
                                                     │
                                              还不成 → 告警留给人
```

## 要实现什么

| 目标 | 机制 | 算完成的标准 |
|---|---|---|
| 换模型不用重启 | 注入 `/model` 开列表 → 粘贴模型名 → 立刻回车 | 会话缓存的 `pending.model` 变成目标 |
| 推理档位可自动切 | 点开"模型/档位"面板 → 点第二行「推理等级」→ 点固定位置那一行 | `pending.reasoningEffort` 变成目标 |
| 不把档位留在 `off` | 默认禁止切 `off`；每次切完回读，掉到 `off` 立刻拉回原档 | `ops/effort-guard.jsonl` 有记录或根本不会发生 |
| 权限能读、不代推 | 读 `permissions.preset`；切权限只做到"选中"，风险确认留给人 | 程序从不点"我已了解风险"那个勾 |
| 点错也不伤人 | 打字闸门（人 15 秒内动过键鼠就一下不按）+ 无锚点绝不猜坐标 | 两类日志里都看不到"抢了人在打的字" |

## 细节

**为什么用"状态文件"而不是"截图识别"。**
一开始想做屏幕识别：截图 → 找按钮 → 点。实测代价很大：每 0.25 秒抓一张图做像素比对，
叠加本地模型推理与后台抓网页，把整台机器卡死（人当场报「系统卡了」）。
后来改成：**状态文件读得到就不截图**（几十 KB 的 JSON，几乎零开销），
截图只在"核对失败、要看现场"时截**一张**。

**为什么坐标不写死、要锚定"蓝色发送按钮"。**
右下角那排控件的位置随模型名长短左右漂移（`DeepSeek-V4.1-Flash` 和 `DeepSeek-V4-Pro` 差几十像素）。
写死坐标的第一次尝试把"推理等级"点成了"模型"。现在先按颜色找出那颗蓝色发送按钮当锚点，
其余位置全部按"距锚点多少像素"算。

**为什么"直接点行"而不是"按方向键数格子"。**
方向键实测不可靠：从 `low` 按一次 ↓，有时不动、有时直接跳到 `max`。
点固定行稳，而且不会"路过 `off`"（人曾看到档位一闪变成 `Off`，就是回顶动作造成的）。

**打字闸门。**
所有按键脚本进门先问"人多少秒前动过键鼠"，15 秒内动过就一个键都不按。
起因是脚本抢前台 + `Ctrl+A` 把正在输入的一整段变成"全选"，下一键就覆盖了。

**写盘走真路径。**
`C:\SysPersona` 是指向 D 盘的 junction。自动审查会拦"改 C 盘文件"，
所以根目录一律用 `realpath` 解析成 D 盘真路径，日志、账本、镜像全落在真路径下。

## 边界

- **不自动改权限档**：选中可以自动，`我已了解这些风险` 那个勾必须人点；没有替人勾的实现。
- **`off` 不由程序设置**：默认禁止；掉了会被拉回，但不主动切过去。
- **自动切档只有命令行入口**（`--auto mech|dig|deep`），还没挂到定时任务上——"按任务性质自动选档"这一步仍由人/上层判断。
- **只有 DSH 被接管**：Hermes 的同类开关（模型/档位）没做。
- **坐标依赖布局**：换分辨率、缩放比、主题，四行位置要重量；量法写在技能 `screen-read` 里。
- 本版**属功能冻结期的例外**：人明确要求（2026-11-11），理由是"容灾必须能自己把界面扳回去"。冻结原则不变，此后仍只修问题。
## 追加（同日 19:0x）：关机也能由后台执行

人：「比如昨天晚上我通知你关机，或者你把关机也添加到后台程序中」「关机可以测试」。

- **实测不需要管理员**：本机普通用户带 SeShutdownPrivilege，shutdown /s /t 900 排得上；
  排上后 --status 读我们自己的账本（**不再用 shutdown /a 去探测**——那命令本身就是取消，
  旧写法等于看一眼就把人安排的关机撤了，已修）。
- 取消有效：--cancel → shutdown /a，返回 0 并记 ops/power-ops.jsonl。
- **三道保险**：默认 60 秒延迟（可撤）；ops/tasks.jsonl 里还有没做完的任务就拒绝（要强来加 --force --why）；
  每次动作记账（谁点的、延迟几秒、当时几条活）。
- 托盘「本机」下新增两项：**关机（60 秒后，可取消）** / **取消关机**。
- 注销（shutdown /l）也支持，但**不进菜单**：本机只有一个账户，注销没人再点回来。
