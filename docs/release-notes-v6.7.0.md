# v6.7.0 · 清理：先搬后删

> **这一版只回答一个问题：怎么在后台清垃圾，既真腾出空间，又永远不出现"删错了拿不回来"？**

---

## 一、设计思想

人给了两条口径，这一版就是照它们写的：
「清理加入日常任务，但是不要实时清理，最少保留 3 天或者一个星期，以免误删」
「或者清理是先移动到清理文件夹，然后确认没误删后再删除」。

所以这一版的核心不是"加个定时清理"，而是**把"删除"拆成两个可验证的动作**：

- **移动可撤销，删除不可撤销** → 先移动，中间留一个 7 天的窗口；
- **后台动刀子之前先给自己上闸** → 年龄闸（够老）、时段闸（夜里）、频率闸（一天一次）、体量闸（超了停）；
- **白名单而非黑名单** → 只认 `*.tmp` / `*.partial` 这类名字；宁可少清，不可多清；
- **每一步都能自证** → 清单（原路径/大小/sha256/年龄）+ 日志（搬了什么、删了什么、还原了什么）。

## 二、步骤（一条链路）

```
守护每小时看一眼
   │
   ├─ 日期闸：今天已经动过？ ── 是 → 什么都不做
   ├─ 时段闸：还没到 4 点？  ── 是 → 什么都不做
   │
   ├─① sweep：候选 = 白名单 ∧ 年龄 ≥ 7 天（∧ 不在禁收名单里）
   │     超过 500 个 / 2 GB → 停，写 janitor-stop.json，等人
   │     否则：移动到 清理/待删/<批次>/，写清单 —— 不删任何东西
   │
   └─② purge：筐里放满 7 天的批次 → 真删，写日志
          ↳ 任何时候 restore --batch <批次> 可整批还原
```

## 三、要实现什么（目标 → 机制）

| 目标 | 机制 | 算完成 |
|---|---|---|
| 误删能救回来 | 先移动到 `清理/待删/<批次>/` + 清单 | `restore --batch` 后文件回到原位、内容一致 |
| 不实时清理 | 日期闸（一天一次）+ 时段闸（4 点后） | 同一个自然日第二次调用直接空操作 |
| 不删正在用的 | 年龄闸 ≥ 7 天（**不许小于 3**） | 1 小时前的 `.tmp` 不动 |
| 空间真回收 | 第二段 `purge` 只删放满 `keep-days` 的批次 | 筐里批次变少、磁盘可用空间变大 |
| 后台不自伤 | 体量闸 500 个 / 2 GB，超了停下等人 | 造 600 个候选 → 返回 3 且不搬 |
| 不碰要命的文件 | `NEVER` 正则（索引本体、压缩包、模型权重、数据库） | 即使名字像垃圾也不进候选 |

## 四、细节（按职责）

**候选判定**：只认四种名字（`*.tmp`、`*.tmp.<hex>`、`*.partial`、`*.crdownload`），再叠年龄闸。
`.git/` 与 `清理/` 自身不入扫描，避免"把清理筐自己又清一遍"。

**清单与哈希**：每个被搬的文件记 `from/to/size/age`；小于 50 MB 的算真 sha256，
更大的（比如 900 MB 的索引残片）只记"大小 + mtime"并标出来——在小主机上给 900 MB 算哈希要十几秒，
宁可少一个哈希，也不让清理把机器拖住。

**还原**：逐条搬回原位，**已存在同名文件就不覆盖**（报冲突），因为"覆盖"是另一种不可撤销。

**日志**：`ops/janitor-log.jsonl` 每行一条（`move` / `move-fail` / `purge` / `restore`），
可以事后回答"三天前那个文件去哪了"。

## 五、证据

端到端实测（造一个 10 天前的 `probe.tmp` 走完整条链）：

```
$ python persona_janitor.py sweep --apply --min-age-days 3
执行：候选 1 个 / 0.0 MB → …\清理\待删\20261112-1914
  ops\_janitor-test\probe.tmp       0.0 MB   10.0 天
已搬 1 个 进筐。清单：清理\清单\20261112-1914.json；7 天后才真删。

$ python persona_janitor.py status --min-age-days 3
候选：0 个          ← 已搬走
筐里：20261112-1914  1 个  已放 0.0 天

$ python persona_janitor.py restore --batch 20261112-1914 --apply
已还原：可还原 1 个 · 冲突 0        ← 文件回到原位（Test-Path = True）

$ python persona_janitor.py purge --apply --keep-days 7
筐里没有放满 7 天的批次，不删任何东西。
```

真实场景（本机 2026-11-12）：`index/vectors.tmp`（900.9 MB）与 `index/meta.jsonl.tmp`（239 MB）**当天生成**，
按年龄闸**一个都没动**——这正是"不要实时清理"要的效果；它们要等到满 7 天才进筐、再放 7 天才真删。

## 六、边界

- **不动**备份压缩包的保留策略（那是"删备份"，要单独定），本版只清临时垃圾；
- **不动**索引本体（索引可重建，但重建很贵，不由清道夫决定）；
- 只清本机这一个库根，不做跨盘/跨节点清理；
- 不提供"按扩展名批量清"的通用模式——白名单是故意的，避免一次配置失误清掉整个目录。
