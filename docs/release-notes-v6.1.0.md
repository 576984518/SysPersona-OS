## 一句话设问

**这套东西怎么跟一个具体的第三方客户端配合、再加一个该怎么加；真出事的时候往哪退、退到哪、怎么看得见。**

## 设计思想

它不能修改别人的客户端，也不该把自己的逻辑塞进别人壳里。所以只能做一件事：把"怎么和一个客户端相处"写成契约——一个客户端就是一段配置加一份能力声明；方法不通用，就分别写，不假装有统一接口。

容灾那一边守三条。**先保通路**：能回话比能干活重要，通路断了别的都谈不上。**降级必须可见**：偷偷降级比不降级更坏，它会让人以为一切正常。**断网也能跑才算容灾**：要联网才成立的"容灾"，是设计者的自我安慰。

## 客户端接入：一个客户端就是一段配置

一个客户端由四样东西描述：`img` 认进程（它现在跑没跑）、`wm` 找水位（它的上下文用到哪了）、`actions` 定它能做什么、`open` 定会话在哪儿。

自动操作它只有六条路，按"越靠接口越好"排：界面注入、调试口、命令行、只重启内核、拉起网关、进程动作。每条都写清前置条件和失败长什么样——因为**失败的样子比成功的样子更重要**，出事时先认得出是哪一种。

加一个新客户端是五步：填这四项配置、试六种方法里哪几种可用、写下它特有的失败、给一个可核对的判据、验收。示例只给 Hermes（CN 桌面版）：内核 `:9120` 健康检查、调试口发 `/compact`、网关是独立进程、会话在 `hermes-home`。不给第二个例子，是因为没实测过的写法等于编。

## 容灾：四层往下退，每一层都看得见

四层：**进程 → 配置 → 模型 → 通道**。进程层拉起守护；配置层用上一份好的整份替换；模型层沿着 `付费 → 免费档 → 本地` 走，并挂了余额阈值（这台机器上的实际口径是 DeepSeek < ¥5、免费档 < ¥1，不是估算）；通道层断了就本地全功能跑。

配一张断网代班卡：断网时它还能做什么、不能做什么，写在卡上。恢复也有顺序——**网关 → 内核 → 窗口 → 重读**，顺序错了就会出现"窗口在、但规矩是旧的"。七组开关都默认关，要用的人自己开。

## 证据

Hermes 那几条都在本机实测过：内核重启 **21 秒**完成，`GET /api/health` 返回 `{"ok":true}`；压缩与重读走调试口，返回 `SENT`；网关用 `gateway status` 判活、用 VBS 隐藏拉起；版本读到桌面 exe `0.9.0.0` 与内核 `0.21.0-cn.18`（`manifest.json`）。

阈值不是拍出来的，是这台机器上跑出来的：DeepSeek 余额低于 ¥5 触发、免费档低于 ¥1 触发。

## 边界

**不改、不重打包第三方客户端**；能走命令行或接口就不点它的界面按钮。平台只有 Windows 10/11，没有 Linux/macOS 实现，也不依赖云服务。

**自动换档没有交付**：只做到"判定 + 提示 + 换一份可替换的配置"，剩下那一步要人。文档里就这么写，不冒充完成。托盘那一侧的规格重写属于 5.1 线（`docs/TRAY_SPEC.md`），不占本版编号。
