# 进化史：一个在五次断片里长出来的仓库

> 这不是宣传稿，是一份**事故记录**。
> 它记录的不是"AI 多聪明"，而是"上下文一断，它有多蠢"——以及把决策写下来之后，事情变成了什么样。

## 一、起点：它不是忘了内容，是忘了为什么

最初的诉求只有一句：**"聊到一半，窗口满了，开个新会话，它就不认识我了。"**

不是忘了几句话。是忘了：

- 我们为什么不要"更大的上下文窗口"这个方案；
- 为什么"唯一在场"后来变成了两种模式；
- 为什么加密必须可选、又必须声明；
- 哪些方案已经被否决过，以及**否决的理由**。

新会话里的它，读到的是结论，读不到岔路。于是它会把已经死掉的方案再提一遍，而且提得很有道理——因为它不知道那条路已经走过了。

## 四、三个可以验证的观察

**1. 贴合度与上下文密度同向变化，与模型能力无关。**

同一个模型，在会话开头会问"你要哪种存储"，在会话后段会直接说"这条会和你之前的 §13.7 打架"。变的不是智力，是它手里有多少条**已经做过的判断**。

**2. 断片后重建的成本，主要花在"解释为什么"上。**

重述结论很快，重述取舍很慢。这也解释了为什么交接里最值钱的部分不是"当前状态"，而是"不要顺手做的"。

**3. 写下来的才是记忆，窗口里的只是缓存。**

这句话是这个仓库的全部动机。缓存会失效，文件不会。

## 五、一个诚实的保留

**很难把"上下文的功劳"和"仓库变厚的功劳"分开。**

到这个阶段，仓库本身已经有十几份文档、上百条规范，任何一个新会话读完之后，表现都不会差太多。所以更准确的说法是：

> 不是"这个 AI 进化了"，而是"它每次都能把同一份记忆重新读进去"。

这个区别很重要——前者听起来像玄学，后者是可以复现的工程。

## 六、被否掉的主意（比做成的更值得记）

| 当时的想法 | 结论 | 为什么 |
|---|---|---|
| 自研客户端（Vault、Cordis 插件、M1–M4 分层） | 停 | 客户端是最大不确定项，记忆才是资产 |
| 强制对齐 / 微调压制底座性格 | 废 | 换来的是顺从，不是人格 |
| 控制台闪烁上 Cordis 插件 | 不做 | 为少闪几个窗口写常驻 hook，维护成本高于收益 |
| 兜底模型用 4B 保智商 | 改 | 3.2G 权重 + 大上下文在 16G DDR3 上必爆，兜底只为不失联 |
| 把目录 junction 进同步范围 | 否 | `state.db` 带 WAL，被同步抓走会拿到半截快照 |
| 上下文压缩手动触发 | 暂缓 | 延迟工具的嵌套参数，DeepSeek 系模型填不出 |
| 只改几句话就发版 | 禁止 | 版本号是承诺，不是日志 |

## 八、怎么验证这件事

开一个全新会话，只给它三样东西：

- 接续包（`HANDOFF`）
- `CHANGELOG.md`
- 现行规范

然后问它："接着往下做，下一步该干什么？"

- 说得八九不离十 → 压缩过的记忆够用，这套方法是成立的；
- 开始重复已否决的方案 → 缺的不是 token，是**决策记录**。

这个实验谁都能做，不需要相信任何说法。

## 九、所以这个仓库到底在做什么

表面上看，它在定义一种格式：人格与记忆怎么存、怎么加密、怎么迁移、怎么分身、怎么被约束。

往深一层看，它在回答一个问题：

> **当模型可以换、硬件可以换、窗口可以关，什么东西必须留下来，才能让"它"还是"它"？**

答案不是权重，也不是某次对话的全文。是**压缩过的决策历史**——它做过什么、否决过什么、为什么。

记忆不是聊天记录。记忆是"我们为什么走到这里"。

## 十、并行项目：同一个方法的另一次验证

同一段时间里，还有另一个仓库 [`snailstar-j1900-bios`](https://github.com/576984518/snailstar-j1900-bios)：

> 蜗牛星际 B 款双网口（J1900 / NCT5532D）BIOS 热复位修复 + S3 排查记录。

它和这个仓库解决的是完全不同的东西（一块主板的固件缺陷），但**方法一模一样**：

| 步骤 | 在 BIOS 项目里 | 在这个仓库里 |
|---|---|---|
| 定位根因 | `PchReset` 往 `0xCF9` 写 `0x06`，本平台忽略该值 → 死循环 → 看门狗 → 无限重启 | 交接包里只有结论、没有岔路 → 新会话重提已否决方案 |
| 最小改动 | 3 处字节：`0x06 → 0x0E`（两处）+ 跳过胶囊更新路径 | 只加"决策记录"，不改对话流 |
| 留证据 | SHA256、模块偏移、对比同平台固件 | 版本号、实测数字、被否掉的主意 |
| 诚实结论 | **S3 是板级硬件没接 `SLP_S3#`，软件修不了** | 压缩/写回/兜底至今未验收，不吹 |

最后一行是重点：两个项目都出现过"查完发现是硬件/平台限制，软件无解"的结论。
把这种结论写下来，比硬凑一个补丁有价值——**它让别人少走一遍同样的路**。
