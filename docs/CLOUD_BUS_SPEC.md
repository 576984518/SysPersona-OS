# 网盘索引总线 — CLOUD_BUS_SPEC

> 状态：**v5.7.0 已交付**（2026-11-10）。代码 `persona_cloud_bus.py`，规格即本文。
> 这份文件回答一件事：**多个常驻程序怎么在网盘上安全地写索引、读索引，还不会互相踩**。

## 一、要解决什么

不止一台机器、不止一个进程都要往同一份记忆库里写「今天干了什么」。直接让谁都去改同一个文件，
结果必然是覆盖、冲突副本、半截文件。三个硬要求：

1. **任何进程都能写自己的分片**，不用抢；
2. **总索引只有一个人能改**，其余只读；
3. **网盘掉线不能挂死**，写入要能排队、恢复后补交。

## 二、怎么挂网盘（不装官方客户端）

**不用百度网盘官方客户端**——它会在上传未完成时锁住文件，外部进程读到的就是 0 字节或者失败。

用 **rclone** 或 **WebDAV** 把它挂成一个盘符（本机约定 `Z:`）：

```powershell
# rclone 挂载（示意；凭据放 rclone.conf，不进仓库）
rclone mount baidu:SysPersona Z: --vfs-cache-mode writes --dir-cache-time 10s
```

- `--vfs-cache-mode writes`：小文件走本地缓存再上传，避免半截文件；
- `--dir-cache-time 10s`：目录刷新别太懒，否则别的节点写了你看不见；
- 挂载失败时盘符不存在 → 总线自动降级（见 §六），不会把进程卡住。

## 三、目录结构

```
Z:\SysPersona\
├── Hot_Bus\            # 热总线：各进程写自己的分片，独占写、互不覆盖
├── Cold_Backup\        # 冷备：压缩包 / 归档副本
├── Archive\            # 删改一律移到这里，不真删
├── MASTER_INDEX.md     # 总索引（单写手 + 文件锁）
└── .master.lock        # 锁文件
```

**为什么分两个区**：`Hot_Bus\` 是同步软件**必须实时跟**的小文件；`Cold_Backup\` 是**不必实时**的大压缩包。
混在一起会导致同步队列被大文件堵住，热数据反而迟到。

## 四、写入协议

1. **写分片**：文件名 `节点__标题__时间戳.md`，先写 `xxx.tmp`，再 `os.replace` 成正式名——
   原子替换，同步客户端永远看不到半截文件；
2. **更新总索引**：拿到 `.master.lock`（`msvcrt.locking` 非阻塞 + 超时）后，读全部行、
   删掉同名旧行、追加新行、按时间倒序、整体重写（同样是 tmp→rename）；
3. **不放锁就写**：拿不到锁就等 10 秒，超时抛错——宁可这次不写，也不并发改坏总索引；
4. **删改**：一律移动到 `Archive\`，不真删（删记忆必须人点头，见 `DECISIONS` 5.4）。

## 五、读协议

- 读端**只读 `MASTER_INDEX.md`**，按需再去 `Hot_Bus\` 取某一片；
- 总索引最多保留 500 行（按时间倒序），更老的由 GC 线程移进 `Archive\`；
- 读端不做「扫描全目录」——目录扫描在网盘挂载上很贵，且会随文件数线性变慢。

## 六、断网降级（关键）

```
写分片 → 网盘可用？
           ├─ 是 → tmp→rename 写上去 → 更新总索引
           └─ 否 → 追加到本地 ops\cloud-queue.jsonl（不丢、不阻塞）
```

- 判定「可用」= `Z:\SysPersona` 目录存在且可写；
- 恢复后 `python persona_cloud_bus.py --flush` 把队列补交上去，**幂等**（同名分片覆盖 + 总索引重算）；
- 队列文件本身是追加写的 JSONL，进程崩在中间也只坏最后一行（读的时候跳过解析失败的行）。

## 七、与其它线程的关系（解耦）

| 线程 | 干什么 | 与总线的关系 |
|---|---|---|
| `t_capture` | 抓取会话 | 只写 `Hot_Bus\` 分片，不碰总索引 |
| `t_context_gc` | 压缩 / 归档 | 通过总线写「会话总结」分片 |
| `persona_cloud_bus --flush` | 补交队列 | 独立线程 / 定时任务，**不阻塞上面两条** |
| 主节点 | 汇总 | 唯一改写 `MASTER_INDEX.md` 的角色 |

三条线程各自独立；网盘慢只让 `flush` 慢，不会卡住抓取和压缩。

## 八、命令

```powershell
$PY = "$env:USERPROFILE\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe"
$R  = $env:MEM

& $PY $R\persona_cloud_bus.py --status      # 网盘可用？本地排队几条？
& $PY $R\persona_cloud_bus.py --flush       # 补交队列
& $PY $R\persona_cloud_bus.py --read        # 打印总索引（读端只读这个）
& $PY $R\persona_cloud_bus.py --shard "会话总结" --body-file x.md
```

## 九、验收（已实测，2026-11-10）

| 项 | 结果 |
|---|---|
| 断网写入降级 | 指向不存在的 `Z:\SysPersona` → `QUEUED`，本地队列 +1，进程不挂 |
| 恢复后补交 | 目录一存在 → `--flush` 全部补交，队列清空 |
| 三进程并发写 | 3 个进程同时写分片：全部成功，**无 `.conflict` 副本、无残留 `.tmp`** |
| 总索引一致性 | 持锁重写，无重复表头，按时间倒序 |
| 原子写 | 只有 `.md`，没有半截文件 |

## 十、还没做的（如实写）

- **真实网盘挂载未验证**：本机现在没有 `Z:`，全部测试都在临时目录模拟；
- **GC 线程未实现**：`Archive\` 的清理与 500 行截断目前只在写总索引时顺手做，没有独立任务；
- **多机时区**：时间戳用本地时间，跨时区节点会乱序，接第二台机器时改成 UTC 或带时区偏移。
