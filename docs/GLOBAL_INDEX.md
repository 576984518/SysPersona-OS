# 全局索引（GLOBAL INDEX）

> 一句话：**索引是前置放大器——模型再聪明，也答不出没被喂进去的那段。**
> 状态：v5.1.0 起为默认链路；实现在 `tools/ctxpack/persona_index.py` + `persona_index_l1.py` + `persona_search.py`。

## 一、四层，各管一段

| 层 | 产物 | 粒度 | 什么时候读 |
|---|---|---|---|
| L0 正文 | `sessions\日期\来源\*.md` | 一个会话一份 | 直读（热） |
| L1 目录 | `index\L1.md` / `L1.jsonl` | **每个来源一行** | 出接续包时读一次 |
| 块索引 | `index\meta.jsonl` + `vectors.npy` | 按段落切块 | 检索时用 |
| 归档 | `archive\日期\来源\` | 去重副本 | 回查历史 |

L1 存在的意义：**让"只读一次"成为可能**。没有它，接续包里就得塞全量清单，上下文一秒爆掉。

读 L1 的入口是 `persona_master.py`（人读 / `--json`）；**唤醒后第一件事就是读它**，再决定做什么。这也是 v5.3.0 的硬规则：不读索引就认领 = 盲干。

## 二、增量：先记账，再动手

```
文件 → sha256 → 与 index\manifest.json 比对
       ├─ 没变：跳过（0 token）
       └─ 变了：切块 → 嵌向量 → 写临时文件 → 原子替换
```

三条硬规则：

1. **按内容哈希记账**，不是按时间戳——改回旧内容也算没变；
2. **先写临时文件再原子替换**，重建期间旧索引照常可查；
3. **嵌向量只为新增块付费**，实测全量 19170 块 / 121 文件，日常增量 0～几十块。

## 三、检索：两路合并，默认混合

| 路 | 干什么 | 退路 |
|---|---|---|
| 关键词 | IDF 加权 + 回声降权（同一句反复出现不占便宜） | `--no-vector` 纯关键词 |
| 向量 | bge-m3 嵌入 + 余弦 | 断网自动降级为纯关键词 |

合并用 RRF（倒数排名融合），默认 `K=100`。**降级不丢结果**是验收项：断网与联网的 top-20 至少 19 条一致。

## 四、一个必须记住的坑

列目录 → 算哈希 → 写索引，中间文件可能被**归档去重删掉**。
旧版直接 `FileNotFoundError` 退出，而且下一轮还是同一批文件——**永远卡在同一处**。

现在拿不到哈希就跳过，下一轮再算。判据：索引任务连续两轮报同样的 `DONE` 块数，而不是同样的 `FAIL`。

## 五、验收

| 判据 | 怎么验 |
|---|---|
| 增量不重嵌 | 连续跑两次，第二次嵌入 0 块 |
| 索引不断流 | 归档/删除文件后，任务仍 `OK` |
| 检索可用 | 20 题跨文件回归 ≥ 19/20 |
| L1 新鲜 | 出包前自动重建，包里的目录行数 = 当天来源数 |
