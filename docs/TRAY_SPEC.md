# 托盘状态显示 — TRAY_SPEC

> 状态：**v5.1 修订（2026-11-11 重写；同日二次：压缩超时亮红灯 + 自启收敛为"只有一个"）**，实现 `tools/tray/persona_tray_clients.py`（随 v6.1 一并入库，运行版在记忆库根）。
> 这条线是 **5.1 设计 / 5.2 实现**；本次是同一份规格的重写，**不占 6.1 的版本号**。
> 本次（随 v6.1 一并入库）托盘换了做法：**一个我们自己的图标 + 按客户端动态生成的二级菜单**（v5.2 的"几个客户端并排几个方块"已作废）。
> 这份文件回答四件事：托盘是什么、显示什么、菜单怎么长、怎么保证不打扰人。

## 一、定位：状态显示 + 受限操作台，不是智能体

托盘是 **SysPersona-OS 的配套状态板**，用来看着第三方客户端（DSH / Hermes / 以后换的壳）在不在跑、
水位到哪、版本变没变，以及在**受限范围内**帮它做几件事（发一句话、重启内核、拉起网关）。

它不承载对话，不做推理，不跑本地模型。它只做三件事：**看得见、点得动、退得掉**。

## 二、它不自己调模型

**已否决**：托盘内置小模型自己去执行任务。理由：多一个模型依赖、多一份占用，还会和主节点的路由打架。

正确的是路由模型：

```
托盘（状态板）
   └─ 指定一个主节点（主记忆分身 / 某个具体记忆分身）
        └─ 主节点按「能力 + 可用性」把任务派给某个分身
             └─ 完成 → 结果回到主节点 → 回给托盘
                   └─ 该分身掉线 → 主节点自动切到下一个可用的
```

**谁来做，由主节点决定**；托盘只负责把「要什么」和「结果」端到端接好。

## 三、图标：一个，不变，只在异常时变色（5.1 修订）

> 2026-11-11 定，走过三版：同心圆（作废）→ 方块并排（作废）→ **单图标 + 状态色**（现行）。

- 图标永远是**我们自己的那一块**（深色圆角牌 + 白 S），**不轮换、不抽客户端 exe 的图标**；
- 颜色三档：**绿**正常 / **琥珀**留意（水位 ≥70%、水位读数不可用、某个客户端没在运行、成本超线、客户端版本变了）/
  **红**告警（守护停了、注入失败、水位 ≥85%、**压缩超时**）；
- **压缩超时＝红，只亮灯**（2026-11-11 二次修订，人文原话「超时没有压缩，图标直接显示红色报警就可以了」）：
  两条判据任一命中就红——① 水位 ≥70% 且**超过 25 分钟没有真正压缩**；
  ② 6 小时内出现过「连压不降」告警（`ops\compact-alert.json`）。
  **不弹窗、不抢焦点、不自己动手**；托盘只负责报警，压不压由压缩器和人决定。
- 悬停提示：`SysPersona · DSH 12% · Hermes 32% · 正常`（有异常时写"异常 N 项"）；
- 压缩进行中：整块黄 + 固定提示，压完自动回到状态色。

理由：客户端会越来越多，一个客户端一个图标会占满通知区；颜色才是"要我看一眼"的那层信息。

## 四、菜单：一级只放"给谁"，细节进二级（5.1 修订）

```
看状态（总览）
只显示异常
────────────────
DSH      ▸  看状态 / 立即压缩上下文 / 重读设定 / 重启窗口 / 打开这个客户的会话存档
Hermes   ▸  看状态 / 立即压缩上下文 / 重读设定 / 重启内核 / 重启窗口 / 微信网关：重拉 / 打开这个客户的会话存档
────────────────
本机     ▸  任务池（本机全局，谁领谁干）/ 派一条…（进这个池）/ 打开托盘·守护日志
客户端版本 ▸  看版本 / 同步检查 · 版本已确认（清提醒）
────────────────
退出托盘
```

三条规矩：

1. **客户端没在跑，它那一级整项不出现**（不是灰掉）；
2. **一级菜单只随客户端数量增长**，其余收进 `本机` / `客户端版本`，客户端再多也不撑爆；
3. 二级菜单里有什么，由该客户端的配置决定（见 `docs/CLIENT_ADAPTER.md` §二），代码不写死。

**任务池的口径**：托盘只读**本机**池（`ops/tasks.jsonl`，谁领谁干）。服务端/远端任务池**不进托盘**，
要看就单独请求——菜单里出现"服务端任务"会被误读成"本机能干"。

**会话/日志的口径**：会话存档和日志按客户端分，挂在**那个客户端自己的二级菜单**里
（"打开这个客户的会话存档"），不在全局菜单里放一个"打开会话"。

## 五、水位来源（分开取，不混）

| 客户端 | 来源 | 频率 | 过期 |
|---|---|---|---|
| DSH | `persona_gauge.py`（读壳的 `pressureTokens` / 账本） | 60 秒 | 测不到就显示「在跑」 |
| Hermes | 守护写出的 `ops/hctx.json` | 随守护 | 超过 10 分钟视为过期、不用 |
| 其他客户端 | 暂无 | — | 只显示「在跑」，**不算异常** |

## 六、版本检查（5.1 修订）

- 每个客户端记两个版本：exe 的 FileVersion，和它自己的内核/runtime 版本（Hermes 读 `data\versions\*\manifest.json`）；
- 版本或安装路径变了 → 托盘变**琥珀**并提示「X 更新了：旧 → 新（可能要同步）」；
- 「客户端版本 ▸ 看版本 / 同步检查」看明细，「版本已确认（清提醒）」把当前版本记成"人看过"；
- 为什么要它：客户端升级会改接口/格式，我们的操作方法可能失效；不知道它升级了，就只能瞎猜。

## 七、不弹窗铁律（2026-11-10 踩坑后定）

托盘是 `pythonw`（GUI 子系统，**没有控制台**）。它再去 spawn 控制台程序（`tasklist` / `node` /
`cmd` / `powershell` / `clip`），Windows 会给子进程**新建一个黑色控制台窗口**，屏幕上就是一闪一闪。

1. 托盘里所有 `subprocess` 调用一律带 `creationflags=0x08000000`（`CREATE_NO_WINDOW`）；
2. 被托盘调用的脚本内部再 spawn 时同样要带——统一用 `persona_win.py`；
3. 托盘自己**必须**用 `pythonw.exe` 启动。

## 八、边界

- 不写记忆、不改索引、不碰 `ops/*.json` 以外的数据；
- 不点客户端界面按钮、不替它确认；
- 不在客户端生成中途重启它（会留下永远卡住的消息），重启前先查轮次租约，有活先等；
- 不内置模型、不直连 API。

## 九、失败时的行为

| 情况 | 托盘表现 |
|---|---|
| 状态文件缺失 | 灰色图标，不报错、不重试 |
| 守护进程死了 | 红 + 标题写「守护异常」，**托盘不负责拉起**（那是看门狗的活） |
| 某任务 `ok=false` 但属设计如此（如 `agent` 只报不拉、余额页抓不到） | 琥珀 + 列进「只显示异常」，不刷红 |
| 客户端进程不在 | 该客户端那一级消失，tooltip 写「X 没在跑」 |
| 客户端版本变了 | 琥珀 + 「X 更新了」，等人确认 |
| **压缩超时**（水位 ≥70% 且 25 分钟没真压；或 6 小时内连压不降） | **红** + 「压缩：超时未压」/「压缩：连压不降」，只亮灯，不弹窗、不代按 |
| I/O 门没在听 | 琥珀 + 「门没在听」（门由守护 `gate` 任务保活，托盘不再负责拉） |

## 十、开机自启（2026-11-11 收敛为"只有一个"）

**启动项只留一个**：`%APPDATA%\…\Startup\SysPersona-Daemon.lnk` → 拉起后台守护；
**计划任务也只留一个** `SysPersona-Daemon`（每 5 分钟 `--ensure`，不在就拉起）。

托盘、I/O 门、CDP、模型表刷新全部由守护按需拉起（`tray` / `gate` / `cdp` / `sfmodels` 四个任务），
不再各自占一个计划任务或启动项——人 2026-11-11 原话：「后台任务，只保留一个」「现在太分散了」。
（Hermes 自己的 `Hermes_Gateway.vbs` 是它的启动项，不动。）

自检：`pythonw persona_tray.py --status` 只打印一帧状态然后退出（不进托盘），用来验证数据源通不通。
