# 托盘（控制台）设计 — TRAY_SPEC

> 状态：**设计成文，v5.1.0 补发**。实现分版推进：v5.2.0 已交付状态灯，v5.3+ 逐个加小功能。
> 这份文件回答一件事：托盘是什么、不是什么、由谁决定把活派给谁。

## 一、定位：控制台，不是智能体

托盘是 **SysPersona-OS 的配套控制台**，用来管第三方智能体程序（Hermes / DSH / 以后换的壳）。

它不承载对话，不做推理，不跑本地模型。它只做三件事：**看得见、点得动、退得掉**。

## 二、它不自己调模型

**已否决**：托盘内置小模型自己去执行任务。
理由：多一个模型依赖，多一份显存/内存占用，还会和主节点的路由打架。

正确的是路由模型：

```
托盘（控制台）
   └─ 指定一个主节点（主人格 / 某个具体人格分身）
        └─ 主节点按「能力 + 可用性」把任务派给某个分身
             └─ 完成 → 结果回到主节点 → 回给托盘
                   └─ 该分身掉线 → 主节点自动切到下一个可用的
```

**谁来做，由主节点决定**；托盘只负责把「要什么」和「结果」端到端接好。

## 四、边界

- 不写记忆、不改索引、不碰 `ops/*.json` 以外的数据；
- 不做界面注入、不替换字体（那属于本地私有适配，不进仓库）；
- 不内置模型、不直连 API；
- 状态来源只有一处：守护进程写出的 `ops/persona-status.json`。

## 五、失败时的行为

- 状态文件缺失 → 灰色「读取中」，不报错、不重试；
- 守护进程死了 → 红色「守护可能已停」，托盘不负责拉起（拉起是守护自己的看门狗在管）；
- 主节点掉线 → 由主节点侧切到备用分身，托盘只显示「已切换」。
