# 使用说明·日常这一侧（装好之后怎么用）

> 这份接在 [`docs/USAGE.md`](USAGE.md) 后面。
> USAGE.md 讲的是**部署阶段**：把仓库交给智能体、它怎么盘点环境、怎么验收。
> 这份讲**使用阶段**：客户端接上之后，怎么让它读到设定、怎么知道去哪读文件、以后每次怎么续上。
>
> 文中 `<记忆库根>` = 你自己定的记忆库目录（例：`D:\SysPersona`，脚本用 `SYSPERSONA_ROOT` 找它）；
> `<仓库>` = 本仓库目录。别照抄示例路径。

---

## 一、先把一个客户端接上

能干活的客户端（能读写文件、能执行命令）才有意义；纯聊天的网页版只能靠抓取，给不了它记忆。

### 1.1 登记它（一次，改一个 JSON）

文件：`<记忆库根>\ops\tray-clients.json`，`clients` 下加一块：

```json
"你的客户端": {
  "on": true,
  "label": "显示名",
  "img": ["进程名.exe"],
  "wm": "窗口名片段",
  "open": { "sessions": "会话库相对路径" },
  "actions": { "status": true, "compact": "inject", "reload": "inject" },
  "detect": {
    "exe":     ["完整 exe 路径"],
    "home":    ["它的家目录"],
    "config":  ["它的配置文件"],
    "workdir": ["它默认在哪跑"],
    "auto_launch": false
  }
}
```

验证：

```powershell
python <仓库>\tools\ctxpack\persona_client_probe.py check
# 期望：OK  你的客户端  exe=有｜config=…｜workdir=…｜跑着=是｜版本=…
# 出现 MISS 就是 detect 里 exe / config 写错了
```

### 1.2 两条链要分清

| 链 | 干什么 | 靠什么 |
|---|---|---|
| **本机客户端**（DSH / Hermes 这类） | 它的会话文件被导出 → 归档 → 索引 | `export` + `index` 任务，全在本机，不碰网络 |
| **网页客户端**（DeepSeek / 千问网页） | 靠浏览器抓取 | CDP 抓取；**登录只能人做**，抓取频率建议按需（人按 F5 才抓），别做随机高频 |

> 高频自动抓取是最像爬虫的行为，容易触发站点的风控（同一账号多设备会话会被一起踢下线）。
> 这条是踩过的坑，不是理论。

## 二、第一次：让它认路、读到设定

### 2.1 把这一段贴进客户端

```
记忆根：<记忆库根>

开工顺序（每次接活前，按这个顺序读，不要跳）：
  0) 先看有没有新内容：python <仓库>\tools\ctxpack\persona_readnew.py
     exit 0 = 有新内容，先读完再说；exit 2 = 没有
  1) memory\设定\00-索引.md          —— 目录，先看它
  2) memory\设定\10-人格与红线.md
  3) memory\设定\20-交流与要求.md
  4) memory\设定\30-流程与运维.md
  5) memory\设定\40-事实与现状.md
  6) 文档\LATEST.md                  —— 最近发生了什么（脚本每分钟刷新）
  7) memory\shell\MEMORY.md          —— 常驻短记忆（有字数上限）

要查历史，别整篇读：
  python <仓库>\tools\persona\persona_master.py --k 10     # 总索引：最近 10 条动静
  python <仓库>\tools\ctxpack\persona_search.py <关键词>    # 只取命中片段，再决定读不读原文

红线（做不到就别动手）：
  · 不删、不清理任何记忆与文件；删必须人确认
  · 不改 kernel.json、不改人格身份、不改交接文件格式——只给 diff，等人点头
  · 说「已完成」必须附可复核的证据（数字 / 时间戳 / 退出码）
```

**为什么是这一段**：它把「我是谁（设定）」「现在到哪了（LATEST）」「以前说过什么（检索）」钉成固定动作。
换哪个模型、哪个客户端接手，读的都是同一批文件——这就是「同一个」的来处。

### 2.2 它会读到什么

| 顺序 | 文件 | 一句话 |
|---|---|---|
| 0 | `persona_readnew.py` 的输出 | 有没有新内容 |
| 1 | `memory\设定\00-索引.md` | 目录本身 |
| 2–5 | `memory\设定\10/20/30/40-*.md` | 人格红线 / 交流要求 / 流程运维 / 事实现状 |
| 6 | `文档\LATEST.md` | 最近几条 + 状态，守护重写 |
| 7 | `memory\shell\MEMORY.md` | 常驻短记忆（约 2000 字上限，满了要往外搬） |
| 查 | `persona_master.py` / `persona_search.py` | 总索引 / 命中片段 |

### 2.3 验收：问它三句话

1. **「我是谁？」** → 它该复述人格与红线里的内容，而不是自己发明；
2. **「上次做到哪了？」** → 它该引用 `LATEST.md` 或最近一条记录；
3. **「我不喜欢什么？」** → 它该说出交流要求里的具体条目。

三句都过 = 记忆接通了。任何一句含糊，去看它到底读没读（有没有 readnew / search 的痕迹）。

## 三、后面怎么续

### 3.1 同一个客户端接着聊

每次接活前它自己做的三件：读新内容 → 读 `LATEST.md` → 需要细节才检索。
人这边只需要：刷新了就说一声（或按约定打一个标记），剩下的交给它。

### 3.2 换窗口 / 换客户端

| 步 | 做什么 |
|---|---|
| 1 | 出接续包：`persona_gauge.py --prepare`（一般会自动复制到剪贴板） |
| 2 | 新窗口第一句：贴接续包，或让它读 `续接\接续包-最新.md` |
| 3 | 它该做的：**醒 → 报 → 领**——先报「我在哪、上次到哪」，再领任务 |
| 4 | 索引门：两次核对（派发时读过没有 / 接活时读的时刻晚于派发） |

**接续包有字数上限**，装不下的待办摊在 `续接\待办备忘.md`——新窗口要它顺手读这份，
**别只信交接包的截断**。

### 3.3 崩了 / 被踢下线 / 重启之后

判据只有一条：**文件在 = 记忆在**。重新接上是三步，不是重新交代：

```powershell
python <仓库>\tools\ctxpack\persona_selfcheck.py    # 先确认机器健康
python <仓库>\tools\persona\persona_master.py --k 5 # 看最近发生了什么
# 然后按第二节那套顺序读一遍
```

不用重新告诉它「你是谁、我们做到哪」——那些在文件里。

### 3.4 给新客户端多少东西（三档）

| 档 | 给什么 | 适合 |
|---|---|---|
| 最小 | 记忆根 + `memory\设定\00-索引.md` | 只让它记事 |
| 标准 | 最小 + 四份设定 + `LATEST.md` + 检索两条命令 | 日常对话、接着干活 |
| 完整 | 标准 + [`docs/SKILLS.md`](SKILLS.md) + `程序对照表` + 自检清单 | 让它自己排障、自己修 |

**先给最小档，不够再加**——一次灌太多，它会挑着读、跳过设定。
