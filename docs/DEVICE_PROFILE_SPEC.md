# 不同设备的不同配置（DEVICE PROFILE SPEC）— v6.6.0

> **这一页只回答一个问题：同一份记忆库，凭什么在一台 4 GB 内存的小主机和一台工作站上"各按各的来"，而不用每次换机就手改脚本？**

---

## 一、要解决的三件事

1. **配置不能跟着机器走，也不能跟着人走**：机器一重装，路径、变量全没了，过去每换一台就要改一遍脚本。
2. **"装了"不等于"要用"**：同一台机器上可能装着 Hermes / Herdsman / 本地模型，但小主机跑不动——必须能声明"装了但本机不用"。
3. **探测不能猜**：探不到就写 `null`，不许拿一个"看起来能跑"的路径冒充；否则错误会被带进备份、带进下一次部署。

## 二、四层：默认 → 探测 → 机器档 → 生效

| 层 | 在哪 | 谁改 | 活多久 | 里面有什么 |
|---|---|---|---|---|
| 默认 | `配置/_默认.json` | 人（只加键） | 永久（跟库/同步盘） | **只有键名与"该找什么"，零机器路径** |
| 探测 | 运行时算出来 | 程序 | 不落地 | 环境变量 → 每块盘的常见位置 → PATH → `null` |
| 机器档 | `配置/机器/<指纹>.json` | `new`/`apply` 生成，人可手改 | 跟库走，**重装不丢** | 本机实际路径 + 身份指纹 + 策略 |
| 生效 | `<LOCALAPPDATA>/SysPersona/paths.json` + 用户级环境变量 | 由机器档生成 | 重装即失，跑一次 `new` 即回 | 程序真正读的那份 |

**顺序不可颠倒**：默认只描述"该找什么"，探测只负责"这台机器上在哪"，机器档是**唯一**记录"这台机器就是这样"的地方，
生效层永远是**产物**、不是源。

## 三、身份：两组证据，任一组成立即同一台

| 组 | 信号 | 命中即成立 |
|---|---|---|
| 硬件 | CPUID · 主板序列号/UUID · **全部物理网卡 MAC** · 全部硬盘序列号 | 任意一个对上 |
| 身份 | 系统 MachineGuid · 计算机名 · 账户名 | 任意一个对上 |

- **硬件没变、重装系统** → 硬件组命中 → 同一台（MachineGuid 变了也无所谓）；
- **系统没变、硬件换了** → 身份组命中 → 同一台，但记一笔「换硬件」；id 不变；
- **两组全不沾** → 才是新机器；
- id 一旦定下**不再随指纹漂移**（先认后算）；主板/BIOS 报 `To be filled by O.E.M.`、UUID 是白牌通用占位值时**不采信**。

## 四、策略层：装了 ≠ 要用

机器档里可以写一段**策略**，表述"这台机器上某个重客户端不启用"：

```json
"clients": {
  "hermes":      { "enabled": false, "why": "4G 内存太小，桌面端本机不启用" },
  "herdsman":    { "enabled": false, "why": "同上" },
  "local_model": { "enabled": false, "why": "权重十几 GB，本机跑不动" }
}
```

- **没写这一段 = 启用**（新机器默认照旧，不会因为加了这条就变成什么都不跑）；
- 写了 `enabled: false` 的地方，后台任务**整条跳过**，消息写「跳过：本机不启用（why）」——**不是报红，也不是"没装"**；
- 策略是**人的决定**，探测不会自己编一个：`new` 重跑时**保留**上一份的 `clients`。

## 五、探测的两个已知坑（都已在实现里修掉）

1. **`%ProgramData%` 不在系统盘**：变量展开在 C 盘，而客户端装在另一块盘的 `ProgramData` 下。
   修法：把每块**存在**盘上的 `ProgramData` 都试一遍，**存在才算**。
2. **"探不到"被当成"不存在"**：某机器家目录探不到时被判成"没装"，于是天天按"没装"跳过。
   修法：区分三态——**没装（不存在）** / **装了但本机不用（策略）** / **装了且在用**。

## 六、换机 / 重装的动作

```bash
python persona_machine.py show      # 我是谁 + 现在生效的是什么（只读）
python persona_machine.py detect    # 只探测：哪项没找到，先解决它
python persona_machine.py new       # 生成/更新本机档并应用（保留 created/label/clients）
python persona_machine.py diff      # 机器档 vs 现实，是否有漂移
python persona_machine.py list      # 登记过哪些机器
python persona_machine.py apply --id <id>   # 应用某一份（写 paths.json + 用户环境变量）
```

写 `paths.json` 之前**先备份**旧的一份到 `配置/机器/<id>.paths.json.bak-<时间>`，坏了一条命令回滚。

## 七、边界

- 密钥**不进任何一层**：只写用户级环境变量（注册表），不写 JSON、不进库、不进包；
- 不同机器的策略**可以完全不同**，本页不追求"统一配置"——统一的是**键名**，不是**值**；
- 不做跨机器自动合并配置文件：两份机器档冲突就停下报人；
- 设备运行学的整体口径见 `DEVICE_RUNTIME_SPEC.md`，本页只管**配置怎么分层**。
