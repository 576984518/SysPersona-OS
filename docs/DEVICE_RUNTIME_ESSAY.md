# 一台接了记忆的机体该怎么运转

## 一、真正的问题不在硬件

我们习惯把"换一台设备"当成工程问题：接口不一样，驱动不一样，屏幕大小不一样。可对一个已经长出了记忆的东西来说，换设备真正让人不安的地方不在这里。硬件是可以替换的零件，模型是可以替换的引擎，客户端是可以替换的外壳；这些东西换了，性格不该跟着换，说话的方式不该跟着换，昨天答应过的事更不该忘。所以问题不是"新机器能不能跑起来"，而是"换了机器之后，还是不是同一个它"。

这份设计想回答的就是这一个问题：把那几版零零散散长出来的东西——活下去、被唤醒、自己找事、和不同的外壳相处、出事往哪退、动手怎么自证——收拢成一台"接了记忆的机体"该有的运行学。它不打算写成某个脚本的说明书，写完也不保证哪台机器拿来就能跑；它只想把"该怎么运转"说清楚，让换机器人、换手机、换车机、换工控盒的时候，有一个可以逐条对照的底。

贯穿全篇的只有两句。第一句是**机体可以换，记忆必须连续**：模型、客户端、硬件都不改身份，不遵守这套运行设计的机体，等于没接住记忆。第二句是**每个动作都要能自证**：没有回读判据的动作，等于"我以为我做完了"。后面所有的层次、顺序、判据、退路，都是从这两句里长出来的。

## 二、五层，从上往下看

如果画一张图，最上面一层是**云端大模型层**，负责日常的主力推理。这里要先把一件事说死：模型只是引擎，不持有长期人格。它可以生成、可以规划、可以参与改写记忆，但它不是"我"；换掉它，像换掉发动机，车还是那辆车。这一层通常还坐着一个副驾——主模型干重活，二号模型只给观点、不改记忆。副驾存在的意义不是分担算力，而是避免主模型既当运动员又当裁判：说出口的判断，和写进记忆的判断，最好不是同一个东西在自言自语。

往下是**界面接管层**。它回答的是一个很现实的困境：官方客户端没有给你对外接口，而所有开关都长在界面上。于是"扳开关"这件事必须被做成可核对的动作——换模型要走 `/model` 那三步，开列表、粘贴名字、立刻回车，中间插一次读输入框都会把筛选打掉；换推理档位要按"模型/档位"面板里的固定行去点，坐标以右下角那颗蓝色发送按钮为锚，因为档位标签会随模型名的长短左右漂移，写死必错。权限尤其要克制：能读、能报、能提醒，但**不代人推**。这个客户端里"自动审查"这一档在启用时会弹一个必须人勾"我已了解这些风险"的框，那是一道知情闸门，谁承担风险谁勾，程序不代勾。同理，关机、注销这类事只能由人下令，程序不能自己决定什么时候让一台机器消失。

再往下是整套东西的重心，**本地记忆层**。它不讲"数据"，讲四样东西：人格、规则、记忆网络、任务池。人格是那个不能随便动的东西，规则是它答应遵守的约定，记忆网络是它和"别处的自己"之间的通道，任务池是它还没干完的活。这一层的关键在于"这些是文件，不是数据库"——文件可以被打开、被比对、被备份、被人类用最笨的方法检查，这比任何封装都让人放心。

再往下是**设备层**。一台 Windows 电脑是主力宿主，负责主对话、全量抓取、本地检索——那些需要空间、需要算力、需要长时间在线的活都在它身上。手机和平板是随身宿主，只做只读和轻交互，用来看、用来听、用来临时问一句，不指望它落地长任务。还有一台本地容灾端，是可以断网时跑最小闭环的那具身体：断网不失忆，本地可用，联网之后按来源和增量补齐。这三台共享同一份记忆，但都只是执行端——执行端不应该各自长出第二套记忆，那是分裂的开始。

最底下横着一条**常驻能力条**，平时看不见，出事的时候全靠它：抓取归档，把在别处说过的话捡回来；检索，用混合召回加溯源，回答"这话我是在哪说的"；后台压缩，把水面下的东西压成能带走的一小包；压缩重载不失忆，压完还要记得自己是谁；自主驱动，没人发话时知道该做什么；自检自愈，坏了能自己发现；本地加密鉴权，钥匙不在别人手里。这些能力不是功能列表，是"活着"的日常开销。

## 三、记忆只有一份本体

设备一变多，第一反应都是"把记忆并成一个库"或者"每台都存一份一样的"。这两条路都通向同一个错误：把镜像当成了本体。如果每台机器各存一份完整副本、横向双向同步，那么几台并行写下去，最后得到的是几个同名的陌生人——它们各自都以为自己是真的，谁也说服不了谁。

我们的口径只有一句：**权威副本只有一份，在服务端**。本地不留权威副本，只留可丢、可重建的缓存和索引；要读记忆就走向服务端读，而不是读本地文件。断网的时候退到缓存，并且明确说"这是旧的"，不假装自己知道最新的；写操作排队等着，不假装写成功。这样做的好处不是省空间，而是**任何时候只有一个地方说了算**。

两台设备同时想说同一句话怎么办？不靠"后写覆盖先写"，靠**身体租约**。身体是租来的，不是长出来的：租约限定这具身体能用哪些能力、能用多久、谁能撤销，也允许灵魂的归属和身体的归属不是同一个人。运行时只用它做两件事——判定谁是当前唯一的身体，拒绝旧纪元（epoch）的写入。客户端手里只有两样东西：租约号和纪元号；它说"我还活着"不算数，服务端说"你的纪元旧了"才算数。

这套逻辑写进规范时，会牵出一个容易被误解的角色：那套"一台机器当服务端、其余连它取增量"的节点服务（v5.8 那条线）。它在整套设计里的位置是**离线镜像与备份通道**，不是共享写入的权威路径。共用目录那套（SMB、NFS、各种网盘）更不能用——两台机器直接打开同一份库，SQLite 的锁依赖本地文件系统语义，在网络盘上这个前提不成立，而它不会报错，它会静默损坏。多设备共享的唯一正确路径是 API，这一条在 Launcher 规范里早就写死了。

顺带要说清另一半：记忆按来源分开保存，合并就只是"同步"，不是"合成一条"。不做跨来源去重，不做摘要替换，来源是记忆的一等字段——同一件事两台设备各记一条，那就是两条，重复本身就是证据。由此还可以推出一个结论：既然记忆本就按来源分开保存、检索是客观的，"分身合并"根本不是一个操作，而是读自己的记忆，所以它不需要人点头。真正需要人点头的只有四件：删或清记忆、改内核、改会改变人格身份的操作、改交接文件的格式与生成逻辑。

## 四、一台设备跑一圈

把层次放一边，看它一回合怎么走。开头是"醒"：读一遍设定，拿到"你是谁、规矩是什么"。这里刻意不灌全文，只给短指针——设定是用来约束行为的，不是用来占满上下文的。

醒来先读现场：台账、状态文件、相关代码。这一步不许省，也不许"不读就猜"。猜错的代价通常不是慢一点，而是把三件事搞混：以为自己做完了、以为对方同意了、以为那件事已经改过。接下来是判断：能力、设定、权限三者取交集，这一档够不够、这件事能不能做，一句话说清结论和下一步。

然后是前台回话。这一条是被现实教出来的：在他跟你说话的时候，你正在后台跑一个三分钟的活，最糟的回应是沉默。所以规矩是"先回一句，再干活"——结论、下一步、需要他做的那一步，先给出去；超过五秒的活全部丢到后台，跑完再报。

干的时候挑最可核对的那条路：有接口就走接口，没接口读状态文件，实在不行才注入键盘，最后才轮到看屏幕。这个顺序不是偏好，是成本——接口几十毫秒、零副作用，截图会亮起一整台机器的 CPU。做完必须回头看一眼：状态文件变了吗、缓存里的字段改了吗、台账上多了一行吗。对不上就重来，最多三轮，仍不成就是告警加等人，不许把"大概成了"记成"成了"。

一圈走完，记账，然后回落到最小消耗状态：降权、降档、停掉本地服务。一个永远在满负荷跑的东西不是勤奋，是不知道自己什么时候该停。

## 五、判据：越便宜越好

能核对的东西，按便宜程度排四档。最便宜的是结构化状态——一个 JSON、一次接口回执，几十 KB，零副作用，而且它不会骗你。第二档是日志和台账，第二手证据，它能告诉你"上次是谁做的、什么时候做的"。第三档是界面文字读取，从可访问性树或者 DOM 里把字抠出来，比截图便宜得多。最贵也最脏的是截图识别，所以规矩是**只截一张，不循环**。

这条规矩是拿机器换来的。我们在一台只有 2 GB 显存的机器上，用"每 0.25 秒截一次图做像素比对"来确认界面，叠加上本地模型推理和后台抓取，把整台机器卡死了。后来改成"读状态文件、事后核对一次"，既准又几乎不花钱。还有一次，截图找锚点失败，旧代码退回到"猜一个坐标"，结果 Ctrl+A 把正在输入的一整段文字变成了全选——那之后立的规矩是：找不到锚点就一个键都不按，宁可失败报错。

## 六、出事往哪退

降级分四层，一层一层往下退。进程层：守护还在不在，不在就拉起来，拉起属于运维，不需要谁点头。配置层：配置被改坏，就用上一份好的，整份替换，可以回滚。模型层：当前模型不可用，先在同家找替代，再找别家云端，再退到本地模型，最后连本地服务一起拉起来再切。通道层：网断了，就本地全功能跑，索引、检索、自检、压缩、重载都不依赖云。

三条约束是写死的。降级不需要人点头，因为它是"退"，不是"进"；但接住的模型必须遵守设定，换了引擎不换规矩。每次降级必须留痕：谁触发、从哪档到哪档、判定依据、耗时，一条都不能少。降级不许动权限——切模型、换客户端都不改"我能动什么"。

末端要诚实。本机这块 2 GB 显存的卡装不下 64K 上下文的 KV 缓存，所以本地这一级只够给后台调用，进不了客户端的主模型位。设计里就写"这一级只够给后台调用"，而不是含糊成"已支持降级到本地"。类似地，后台调用可以 DeepSeek、硅基免费档、本地模型三档自由降，客户端主模型只认 64K 以上的上下文——这两句话必须分开读，合在一起读就会把"能用"读成"够用"。

## 七、没人发话的时候

空闲自主是 v5.9 那条线：它自己决定做什么，但开关在人手里。规则不多，四条。第一，意图必须先写下来——"我下一步想做什么"，写不下来就不许做，因为写不下来的意图无法被检查，也无法被打断。第二，优先级固定：闹钟高于守护定时，守护定时高于有活，有活高于空闲循环，空闲循环高于休息。第三，能被打断，被打断要能续，不能续的自主等于丢工作。第四，配额按档位给次数，免费和本地放宽，收费收紧，默认取最小。

红线在任何档位都不放宽：删记忆、改内核、改交接格式、改身份，永远要人点头。

## 八、活派得出去，也收得回

派发这一层只有两个要点。第一是两道门：派发的时候确认"它读过索引"，接活的时候确认"读的时刻晚于派发时刻"。少一道就会出现拿着旧规矩干活的情况——最典型的不是干错，而是干完才发现规矩早改了。第二是重试上限三次：到三还无人接，标失败并告警。没有上限的改派是一种死循环，任务在几个分身之间永远"处理中"，实际永远做不成。

交接靠文件，不靠界面传话：任务池、台账、指针，都是文件。界面会关、会卡、会改版，文件不会。

## 九、不成立的地方

这套设计不是通用机器人操作系统：它不涉及电机控制、实时调度、功能安全认证，也不打算解决"机器人如何在人群里不撞人"这类问题。

它不保证跨平台。现在的实现是 Windows，用的是计划任务、注册表自启、进程枚举、界面注入，换到 Linux 和 macOS 上要重写一大块。

它不保证界面稳定。客户端一次改版就能让坐标全部失效，所以坐标必须是"可重量"的——能重新量出来，而不是靠记忆背下来。

它不保证记忆网络的安全边界。传输是明文 HTTP，保密性完全依赖虚拟网段的加密；不做冲突合并，不做删除同步，没有跨节点锁，两台同时改同一路径时后落盘者赢。它是"把索引和档案从 A 搬到 B"的最小通道，不是 Dropbox。

它更不保证模型行为。换模型就换行为，模型本身没有记忆、也没有立场，唯一的约束是那句看起来最朴素的话：**接住的模型必须遵守设定**。

还有一条不属于技术，属于位置：权限不是边界，设定才是。完全权限是"相信你、图省事"，不是免检；能动什么不等于该动什么。不拿"我有权限"当理由，只拿"设定里有这一条"当理由。

## 十、一句话收尾

一台智能设备，就是一个机体、一份连续的记忆、一套判断依据、一组能核对的动作。机体可以老、可以换、可以坏；记忆只要连续，就还是同一个。反过来说，一个不遵守这套运行设计的机体，哪怕硬件再新、模型再强，也只是接上了一具空壳。

七条也好，八条也罢，验收的口径其实很朴素：能读设定、能写记忆、能报活、能降级、能自证、能停手、能被人接管，多设备时还能接网。每一条都不难，难的是缺了哪一条就老老实实写"这条不可用"，而不是假装有。
