## 零、交接件的定位变了（2026-11-10 改，先说为什么）

**以前是什么**：v3–v5 那条路线的日常是「上下文快满 → 开一个新窗口 → 新窗口开机第一件事是读交接包，靠它把现场、待办接回来（规则本来就在设定文件里，读的是文件）」。
那时候交接包是**每天都要用的一次性桥梁**，断一次就意味着失忆；所以规格里把它写成"开机第一课"。

**现在为什么改**：后台处理把这件事接过去了——到线自己压、压完自己把规矩重新摆到最前面（重置），**同一个窗口就能连着过下去，不用换**。
人不再为了续命去开新窗口，交接包也就从"日常桥梁"退成**灾备**。

**现在的定位（按重要性）**：
1. **崩溃 / 意外断电**：进程没了，靠它把"我们干到哪"捞回来；
2. **换机器**：新电脑上先读交接包，再读索引；
3. **另一台设备接着干**（手机 / 别的分身）；
4. **主动留档**：出大版本、动内核前后各留一份。

**没变的部分**：锁定段（不该变的）与自动段（现场状态）的划分、刷新只覆盖自动段、格式与字段。
变的只是**用它的时机**——从"每天开机第一件事"改成"出事或换地方时才用"。

> **本页是运行规范的子文件**：交接包属于"运行规范"，不是人格规范。
> 正文已收编进仓库；记忆库 `续接\交接文件规范-v2.md` 为镜像，以本页为准。
> 本文件只回答一件事：**交接文件里哪些能改、哪些不能改。**
> 改「锁定段」或改本文件 / `ctxguard.py --prepare` 的输出结构 = **改内核同级**（人点头才动）。
> 改「自动段」的内容是日常操作，AI 可自行更新，但必须守住长度上限。

## 二、自动段（每次出包重生成：正常修改，但限长）

| 段落 | 来源 | 上限 | 更新方式 |
|---|---|---|---|
| 上一轮收尾 | **另一个会话**原文的最后一条助手消息 | ≤300 字 | 自动 |
| 现状 | `DECISIONS.md` 一、最近 4 条 | ≤400 字 | 自动（台账改了包就变） |
| 待办 | `BACKLOG.md` 进行中 + 待办表 | ≤600 字 | 自动（待办改了包就变） |
| 一级索引 | `index/L1.jsonl` 最近 5 条 | ≤350 字 | 自动（`index_l1.py` 重建） |
| 清理提示 | 水位 ≥ `persona_limits.CLEAN`（现行 **300K**，见 `BACKGROUND_SPEC` §二）时生成 | ≤120 字 | 条件生成 |

自动段允许 AI 调整措辞、压缩、换排序；**不允许越过上限，也不允许把锁定段的内容搬进来充数**。

## 三、固定格式（改它 = 改格式，需人确认）

- 章节顺序（0.0 → 〇 → 红线 → 上一轮 → 现状 → 待办 → 一级索引 → 指针）；
- 首句必须是「读完先回一句、然后等指示」；
- 指针段永远保留（会话原文 / 检索命令 / 水位命令）；
- 硬上限 **3600 字**（`PACK_LIMIT`）；超限只截正文，指针必留。

## 四、二次索引（关键：一次交接只读一次索引）

| 层 | 内容 | 何时读 |
|---|---|---|
| **一级** | `index/L1.jsonl`：每源一行（日期 / 来源 / 文件 / 消息数 / 首句） | 交接时**只读这一次** |
| **二级** | `zsearch.py`（混合检索，按需命中片段）/ `HANDOFF.md`（全量摘要） | **需要细节时再读** |

- 一级索引由 `index_l1.py` 重建：82 个来源，**0.5 秒**，不参与打分；
- 一级索引只是"目录"，**不把正文塞进交接包**；
- 二级索引不预热、不缓存进包——用到才查，查完只回命中片段。
